## SmartAbp.DevKit.Cli命令行工具核心功能

`SmartAbp.DevKit.Cli` 是一个企业级代码生成工具，通过命令行接口提供多种核心功能，包括代码生成、批量生成、配置管理、质量门禁检查和部分类管理等。

### generate命令

`generate` 命令用于根据输入的JSON文件生成代码。该命令支持多个参数，包括输入文件路径、输出目录路径、目标平台和详细信息显示。

- **-i, --input**: 指定输入文件路径（JSON格式）。
- **-o, --output**: 指定输出目录路径，默认为`./output`。
- **-p, --platform**: 指定目标平台，支持`web`、`dashboard`、`uniapp`和`backend`，默认为`web`。
- **-v, --verbose**: 显示详细信息。

该命令通过`GenerateCommandHandler`类实现，首先验证平台参数和输入文件，然后读取输入文件并解析为`GenerationContext`对象，最后执行代码生成并将结果保存到指定的输出目录。

### batch-generate命令

`batch-generate` 命令用于从JSON文件批量生成多个实体。该命令支持输入文件路径、输出目录路径和详细信息显示等参数。

- **-i, --input**: 指定输入文件路径（JSON格式）。
- **-o, --output**: 指定输出目录路径，默认为`./output-batch`。
- **-v, --verbose**: 显示详细信息。

该命令通过`BatchGenerateCommandHandler`类实现，首先验证输入文件是否存在，然后读取并解析JSON内容为实体列表，接着创建输出目录，最后逐个生成实体代码并保存到输出目录。

### config命令

`config` 命令用于管理配置，支持列出、显示、获取、设置和初始化配置等操作。

- **action**: 指定操作类型，支持`list`、`show`、`get`、`set`和`init`。
- **-k, --key**: 指定配置键。
- **--value**: 指定配置值。

该命令通过`ConfigCommandHandler`类实现，根据不同的操作类型调用相应的处理方法，如`ShowConfigAsync`、`GetConfigAsync`、`SetConfigAsync`和`InitConfigAsync`。

### quality命令

`quality` 命令用于执行质量门禁检查，确保生成的代码符合企业级标准。该命令支持执行完整的五关质量门禁或单独执行某一关。

- **check**: 执行完整的五关质量门禁。
- **gate1**: 执行第一关：架构完整性检查。
- **gate2**: 执行第二关：代码重复度检查。
- **gate3**: 执行第三关：编译静态检查。
- **gate4**: 执行第四关：packages专项检查。
- **gate5**: 执行第五关：技术债务监控。
- **info**: 显示质量门禁说明。

该命令通过`QualityCommandHandler`类实现，提供了详细的帮助信息和示例，帮助用户理解和使用质量门禁功能。

## devkit.config.json配置文件详解

`devkit.config.json` 文件是`SmartAbp.DevKit.Cli`工具的主要配置文件，定义了代码生成的各种配置选项。

### 配置文件结构

配置文件包含多个配置节，每个配置节对应不同的功能模块：

- **AIFlow**: AI流水线配置，包括超时时间、最大重试次数、断路器设置等。
- **TemplateEngine**: 模板引擎配置，包括模板缓存大小、缓存TTL、是否启用预编译等。
- **QualityGate**: 质量门禁配置，包括是否启用质量门禁、是否启用严格模式、各项检查是否启用等。
- **Performance**: 性能监控配置，包括是否启用性能指标收集、性能警告和错误阈值等。
- **Output**: 输出配置，包括默认输出目录、是否覆盖已存在的文件、是否生成备份等。

### 配置项说明

- **AIFlow.TimeoutSeconds**: 工位执行超时时间（秒），默认为300。
- **AIFlow.MaxRetries**: 最大重试次数，默认为3。
- **TemplateEngine.CacheSize**: 模板缓存大小（LRU），默认为1000。
- **TemplateEngine.CacheTTLMinutes**: 模板缓存TTL（分钟），默认为60。
- **QualityGate.Enabled**: 是否启用质量门禁，默认为true。
- **QualityGate.StrictMode**: 是否启用严格模式（任何警告都会失败），默认为false。
- **Performance.EnableMetrics**: 是否启用性能指标收集，默认为true。
- **Output.DefaultOutputDirectory**: 默认输出目录，默认为`./output`。
- **Output.OverwriteExistingFiles**: 是否覆盖已存在的文件，默认为false。
- **Output.CreateBackup**: 是否生成备份，默认为true。

## 代码生成模板自定义方法与最佳实践

### 模板自定义方法

用户可以通过修改`templates`目录下的模板文件来自定义代码生成的内容。模板文件使用标准的文本模板格式，支持变量替换和条件判断。

1. **创建自定义模板目录**: 在项目根目录下创建`templates`目录。
2. **复制默认模板**: 将默认模板文件复制到自定义模板目录中。
3. **修改模板文件**: 根据需要修改模板文件中的内容。
4. **配置模板路径**: 在`devkit.config.json`中设置`TemplateEngine.TemplateRootDirectory`指向自定义模板目录。

### 最佳实践

- **保持模板简洁**: 模板文件应尽量简洁，避免复杂的逻辑。
- **使用变量替换**: 利用模板引擎的变量替换功能，提高模板的灵活性。
- **测试模板**: 在实际生成代码前，先测试模板文件的正确性。
- **版本控制**: 将自定义模板文件纳入版本控制系统，便于管理和回溯。

## 部分类（Partial Class）生成与合并

### 部分类生成

`SmartAbp.DevKit.Cli` 支持生成部分类，以分离自动生成的代码和用户自定义的代码。自动生成的代码放在`*.Generated.cs`文件中，每次生成时会被覆盖；用户自定义的代码放在`*.cs`文件中，永久保留。

- **Entity.Generated.cs**: 自动生成的代码文件。
- **Entity.cs**: 用户自定义的代码文件。

### 部分类合并

部分类合并功能允许用户在不丢失自定义代码的情况下更新自动生成的代码。合并过程如下：

1. **提取用户自定义区域**: 从现有的`*.cs`文件中提取用户自定义的代码区域。
2. **生成新的自动生成区域**: 根据最新的配置生成新的自动生成代码。
3. **合并代码**: 将新的自动生成代码和提取的用户自定义代码合并到新的`*.cs`文件中。

该功能通过`PartialClassManager`类实现，提供了`GeneratePartialFiles`、`SmartMerge`等方法来处理部分类的生成和合并。

## 工具扩展插件开发指南

### 插件开发步骤

1. **创建插件项目**: 创建一个新的.NET项目，引用`SmartAbp.DevKit.Cli`库。
2. **实现插件接口**: 实现`IPlugin`接口，定义插件的名称、描述和执行逻辑。
3. **注册插件**: 在`plugin`命令中注册新插件。
4. **测试插件**: 使用`devkit plugin run`命令测试插件功能。

### 示例插件

```csharp
public class SamplePlugin : IPlugin
{
    public string Name => "sample";
    public string Description => "A sample plugin";

    public Task<int> ExecuteAsync(string[] args)
    {
        Console.WriteLine("Hello from sample plugin!");
        return Task.FromResult(0);
    }
}
```

## 命令行工具调试技巧与性能优化建议

### 调试技巧

- **启用详细日志**: 使用`-v`或`--verbose`参数启用详细日志输出，帮助定位问题。
- **检查配置文件**: 确保`devkit.config.json`文件存在且格式正确。
- **验证输入文件**: 确保输入的JSON文件符合预期格式。
- **逐步执行**: 对于复杂任务，可以分步执行，逐步验证每一步的结果。

### 性能优化建议

- **启用模板缓存**: 在`devkit.config.json`中启用模板缓存，减少重复解析模板的时间。
- **合理设置超时时间**: 根据实际需求调整`AIFlow.TimeoutSeconds`，避免不必要的等待。
- **使用增量生成**: 启用增量生成功能，只生成变更的文件，提高生成效率。
- **优化输出路径**: 确保输出路径合理，避免频繁的磁盘I/O操作。
