## 开发环境搭建

在开始hxlot项目开发之前，需要正确安装以下开发环境组件：

### .NET 8 SDK安装
项目后端基于.NET 8构建，需要安装.NET 8 SDK。安装步骤如下：
1. 访问[.NET官方网站](https://dotnet.microsoft.com/download)下载.NET 8 SDK
2. 运行安装程序并按照提示完成安装
3. 验证安装：在命令行中执行`dotnet --version`，应显示已安装的.NET版本

### Node.js安装
前端开发需要Node.js环境，建议安装Node.js 18或更高版本：
1. 访问[Node.js官方网站](https://nodejs.org/)下载LTS版本
2. 安装Node.js，npm包管理器将随Node.js一起安装
3. 验证安装：在命令行中执行`node --version`和`npm --version`

### pnpm安装
项目使用pnpm作为包管理器，安装命令如下：
```bash
npm install -g pnpm
```
验证安装：执行`pnpm --version`检查是否安装成功。

### 数据库配置
项目支持多种数据库，可通过脚本进行配置：
- MySQL: 执行`scripts/database/init-mysql.sql`
- PostgreSQL: 执行`scripts/database/init-postgres.sql`
- SQL Server: 运行`scripts/database/setup-windows-sqlserver.ps1`

数据库配置文件位于`config/`目录下，可根据需要修改数据库连接字符串。

## 启动前后端服务

项目提供了两种方式启动开发环境服务。

### 使用start-dev.bat脚本
`scripts/dev/start-dev.bat`是完整的开发环境启动脚本，包含以下功能：
- 检查.NET和Node.js环境
- 自动安装前端依赖（如未安装）
- 启动后端ASP.NET Core服务
- 启动前端Vue.js服务

使用方法：
1. 打开命令行工具
2. 导航到项目根目录
3. 执行`scripts\dev\start-dev.bat`

脚本将自动打开两个命令行窗口，分别运行后端和前端服务。默认访问地址：
- 后端API: https://localhost:44379
- 前端页面: http://localhost:11369

默认登录信息：
- 租户: 留空（主机租户）
- 用户名: admin
- 密码: 1q2w3E*

### 使用start-dev-simple.bat脚本
`scripts/dev/start-dev-simple.bat`是简化版启动脚本，适用于快速启动：
- 自动清理9001和9002端口
- 启动后端服务在http://localhost:9002
- 启动前端服务在http://localhost:9001

使用方法：
```bash
scripts\dev\start-dev-simple.bat
```

此脚本不包含环境检查和依赖安装功能，适合在环境已配置好的情况下快速启动。

## SmartAbp.DevKit.Cli命令行工具

`SmartAbp.DevKit.Cli`是项目的核心命令行工具，用于代码生成、配置管理和质量检查。

### 工具安装
工具可通过以下方式安装：

**方式1：从源码构建（推荐）**
```bash
# 在项目根目录执行
dotnet tool install -g SmartAbp.DevKit.Cli --add-source ./nupkg
```

**方式2：直接运行**
```bash
dotnet run --project src/SmartAbp.DevKit.Cli
```

验证安装：
```bash
devkit --version
```

### 主要命令

#### init命令
初始化DevKit项目，创建`.lowcode/`目录和配置文件：
```bash
devkit init --module-name Product --sample
```

**参数说明：**
- `--module-name`: 模块名称
- `--path`: 项目路径
- `--sample`: 创建示例配置
- `--force`: 强制覆盖已有配置

#### generate命令
生成代码的核心命令：
```bash
devkit generate -i input.json -o ./output -p web -v
```

**参数说明：**
- `-i, --input`: 输入JSON文件路径
- `-o, --output`: 输出目录路径
- `-p, --platform`: 目标平台（web|dashboard|uniapp）
- `-v, --verbose`: 显示详细信息

#### quality命令
执行质量门禁检查：
```bash
devkit quality
```

此命令执行五关强制门禁检查，确保代码质量符合标准。

#### partial命令
管理Partial类：
```bash
devkit partial list        # 列出所有Partial类
devkit partial analyze     # 分析Partial类冲突
devkit partial merge       # 合并Partial类定义
```

#### version命令
显示工具版本信息：
```bash
devkit version
```

## 开发配置选项

`devkit.config.json`文件包含项目开发的核心配置选项。

### 配置文件结构
```json
{
    "namespacePrefix": "SmartAbp",
    "backend": {
        "applicationNamespace": "Application",
        "contractsNamespace": "Application.Contracts",
        "domainNamespace": "Domain.Entities",
        "httpApiNamespace": "HttpApi.Controllers",
        "testsNamespace": "Application.Tests",
        "outputPaths": {
            "Application": "src/{NamespacePrefix}.Application",
            "Contracts": "src/{NamespacePrefix}.Application.Contracts",
            "HttpApi": "src/{NamespacePrefix}.HttpApi",
            "Tests": "src/{NamespacePrefix}.Application.Tests"
        }
    },
    "frontend": {
        "rootPath": "src/{NamespacePrefix}.Vue",
        "viewsPath": "src/views",
        "apiPath": "src/api",
        "typesPath": "src/types",
        "apiBaseUrl": "/api/app"
    },
    "templates": {
        "rootPath": "Templates",
        "backendPath": "Templates/Backend",
        "frontendPath": "Templates/Frontend",
        "useCustomTemplates": false,
        "customTemplatePath": null
    },
    "output": {
        "overwriteExistingFiles": false,
        "createBackups": true,
        "backupPath": ".backup",
        "formatGeneratedCode": true,
        "copyrightHeader": null,
        "logLevel": "Information"
    }
}
```

### 配置项说明

#### 命名空间配置
- `namespacePrefix`: 命名空间前缀，默认为"SmartAbp"
- `backend`: 后端命名空间配置
- `frontend`: 前端路径配置

#### 模板配置
- `useCustomTemplates`: 是否使用自定义模板
- `customTemplatePath`: 自定义模板路径
- `rootPath`: 模板根路径

#### 输出配置
- `overwriteExistingFiles`: 是否覆盖现有文件
- `createBackups`: 是否创建备份
- `backupPath`: 备份文件路径
- `formatGeneratedCode`: 是否格式化生成的代码
- `logLevel`: 日志级别

## 测试执行

项目提供了完整的测试体系，包括单元测试、集成测试和端到端测试。

### 单元测试
前端单元测试使用Vitest框架：
```bash
# 运行单元测试
npm run test

# 运行单元测试并查看覆盖率
npm run test:coverage
```

后端单元测试使用xUnit框架：
```bash
# 在项目根目录运行所有测试
dotnet test
```

### 集成测试
集成测试验证模块间的交互：
```bash
# 运行集成测试
npm run test:run -- --testNamePattern="integration"
```

### 端到端测试
端到端测试使用Cypress框架：
```bash
# 运行Cypress测试
npm run cypress:run

# 开发模式下运行
npm run cypress:open
```

### 自动化测试
项目提供自动化测试脚本：
```bash
# 运行完整的测试套件
node src/SmartAbp.Vue/scripts/test-automation.js
```

自动化测试系统执行以下步骤：
1. 运行单元测试
2. 运行集成测试
3. 运行端到端测试
4. 运行性能测试
5. 生成测试报告

测试报告生成在`test-reports/`目录下，包含详细的测试结果和性能指标。

## 调试技巧与问题排查

### 常见问题及解决方案

#### 端口被占用
如果启动服务时提示端口被占用：
1. 使用`start-dev-simple.bat`脚本，它会自动清理9001和9002端口
2. 或手动执行：
```bash
netstat -ano | findstr ":端口号"
taskkill /F /PID 进程ID
```

#### 依赖安装失败
如果前端依赖安装失败：
1. 检查网络连接
2. 清理npm缓存：`npm cache clean --force`
3. 重新运行`start-dev.bat`脚本

#### 数据库连接问题
如果数据库连接失败：
1. 检查`appsettings.json`中的连接字符串
2. 确认数据库服务已启动
3. 运行`scripts/database/verify-database-config.sh`验证配置

### 调试技巧
1. **后端调试**：在Visual Studio或VS Code中启动调试模式
2. **前端调试**：使用浏览器开发者工具
3. **API调试**：通过Swagger界面（https://localhost:44379/swagger）测试API
4. **日志查看**：检查`Logs/logs.txt`中的运行日志

### 性能优化
运行`scripts/dev/dev-performance-boost.bat`可提升开发环境性能。
