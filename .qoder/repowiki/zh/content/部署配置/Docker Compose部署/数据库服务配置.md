## 项目结构概述

hxlot项目采用多数据库共存架构，通过Docker Compose实现SQL Server、PostgreSQL和MySQL服务的独立部署。项目根目录下的`docker-compose.databases.yml`文件定义了完整的数据库服务配置，`scripts/database/`目录包含各数据库的初始化脚本和管理工具。

## 数据库服务独立配置

### SQL Server服务配置

SQL Server服务采用微软官方镜像`mcr.microsoft.com/mssql/server:2022-latest`，容器名称为`smartabp-sqlserver`，配置了自动重启策略`unless-stopped`。服务通过端口映射`1433:1433`暴露数据库端口，使用环境变量`ACCEPT_EULA: "Y"`接受许可协议，`SA_PASSWORD`设置系统管理员密码，`MSSQL_PID: "Developer"`指定为开发版。

数据持久化通过命名卷`sqlserver-data`实现，挂载到容器内的`/var/opt/mssql`路径。健康检查使用`sqlcmd`工具每10秒检测一次数据库状态，超时5秒，重试10次，启动等待期30秒。

### PostgreSQL服务配置

PostgreSQL服务使用`postgres:15-alpine`轻量级镜像，容器名称为`smartabp-postgres`。通过端口映射`5432:5432`暴露服务，环境变量配置了数据库名称`POSTGRES_DB: smartabp`、用户名`POSTGRES_USER: smartabp_user`和密码`POSTGRES_PASSWORD: SmartAbp@2025`。初始化参数`POSTGRES_INITDB_ARGS`设置了UTF-8编码和C区域设置。

数据持久化使用`postgres-data`命名卷，挂载到`/var/lib/postgresql/data`。健康检查通过`pg_isready`工具检测数据库连接状态。

### MySQL服务配置

MySQL服务基于`mysql:8.0`镜像构建，容器名称为`smartabp-mysql`，通过`3306:3306`端口映射。环境变量配置了root密码、数据库名称、普通用户和密码，字符集设置为`utf8mb4`和`utf8mb4_unicode_ci`。启动命令参数确保使用`mysql_native_password`认证插件。

数据持久化通过`mysql-data`命名卷实现，挂载到`/var/lib/mysql`。健康检查使用`mysqladmin ping`命令检测数据库状态。

## 初始化脚本与环境变量

### 环境变量配置

各数据库服务通过环境变量实现关键配置：
- **SQL Server**: `SA_PASSWORD`设置sa账户密码，`MSSQL_COLLATION`设置排序规则为`Latin1_General_CI_AS`
- **PostgreSQL**: `POSTGRES_PASSWORD`设置密码，`POSTGRES_INITDB_ARGS`配置初始化参数
- **MySQL**: `MYSQL_ROOT_PASSWORD`设置root密码，`MYSQL_CHARACTER_SET_SERVER`和`MYSQL_COLLATION_SERVER`配置字符集

这些环境变量统一使用`SmartAbp@2025`作为密码，确保开发环境的一致性。

### 初始化脚本机制

Docker Compose通过卷挂载机制将初始化脚本注入容器的`/docker-entrypoint-initdb.d/`目录，容器启动时自动执行这些脚本：

- **SQL Server**: `init-sqlserver.sql`脚本创建`SmartAbp`数据库（如果不存在），创建`__DbInfo`信息表并插入版本信息。脚本使用`IF NOT EXISTS`条件确保幂等性，最后输出连接字符串等信息。
- **MySQL**: `init-mysql.sql`脚本创建`__DbInfo`表，使用`CREATE TABLE IF NOT EXISTS`和`INSERT INTO ... VALUES`语句初始化数据，通过`SELECT`语句输出欢迎信息和连接配置。
- **PostgreSQL**: `init-postgres.sql`脚本创建`uuid-ossp`和`pg_trgm`扩展，设置时区为`Asia/Shanghai`，创建`__DbInfo`表并使用`ON CONFLICT DO NOTHING`确保数据不重复插入。

这些初始化脚本不仅创建了必要的数据库结构，还通过输出信息提供了连接指导，便于开发人员快速获取连接参数。

## 网络隔离与连接字符串

### 网络隔离配置

所有数据库服务通过自定义桥接网络`smartabp-network`实现网络隔离和通信。该网络使用`bridge`驱动，确保服务间可以通过容器名称直接通信，同时与外部网络隔离。这种设计既保证了服务间的互操作性，又提供了必要的安全隔离。

各服务通过`depends_on`指令管理启动顺序，如管理工具`pgadmin`和`phpmyadmin`依赖于对应的数据库服务，确保在数据库就绪后才启动。

### 连接字符串配置

根据`CROSS-PLATFORM-DATABASE-GUIDE.md`文档，项目支持跨平台数据库配置，连接字符串根据数据库类型有所不同：

- **SQL Server**: `Server=localhost;Database=SmartAbp;User Id=sa;Password=SmartAbp@2025;TrustServerCertificate=True`
- **PostgreSQL**: `Host=localhost;Database=smartabp;Username=smartabp_user;Password=SmartAbp@2025;Port=5432`
- **MySQL**: `Server=localhost;Port=3306;Database=smartabp;User=smartabp_user;Password=SmartAbp@2025`

`switch-database.sh`脚本提供了数据库切换功能，可以根据参数动态生成对应的数据库配置文件，实现开发环境的快速切换。

## 备份恢复与监控集成

### 备份恢复方案

项目通过Docker命名卷实现数据持久化，为备份恢复提供了基础。`docker-compose.databases.yml`中定义的`postgres-data`、`mysql-data`和`sqlserver-data`卷可以配合Docker卷备份工具实现定期备份。开发人员可以通过`docker volume ls`查看卷状态，使用`docker run --rm -v <volume-name>:/data -v $(pwd):/backup alpine tar czf /backup/backup.tar.gz /data`命令创建备份。

恢复时，可以停止相关服务，删除旧卷，创建新卷并解压备份文件到卷目录，然后重新启动服务。

### 监控代理集成

虽然`docker-compose.databases.yml`未直接包含监控服务，但项目架构支持监控集成。`src/SmartAbp.AspireHost/prometheus/prometheus.yml`配置文件显示了监控系统的抓取配置，包括PostgreSQL Exporter、Redis Exporter等，表明项目支持通过Prometheus监控数据库指标。

健康检查配置为监控系统提供了基础数据源，各服务的健康检查结果可以被Prometheus等监控工具采集，实现对数据库服务状态的实时监控。
