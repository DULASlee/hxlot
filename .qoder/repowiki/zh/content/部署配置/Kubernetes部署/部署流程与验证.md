## Helm部署流程

hxlot项目的Helm部署基于`deployment/k8s/helm/smartabp`目录下的Helm Chart进行。该Chart定义了SmartAbp低代码引擎的完整Kubernetes部署配置，包含前端、后端、数据库、缓存等组件。

### Helm Install

使用`helm install`命令进行首次部署：

```bash
helm install smartabp ./deployment/k8s/helm/smartabp \
  --namespace smartabp \
  --create-namespace \
  --values ./deployment/k8s/helm/smartabp/values.yaml
```

该命令将根据`values.yaml`中的配置部署所有启用的组件。Chart通过`dependencies`字段声明了对Bitnami的PostgreSQL和Redis Chart的依赖，这些依赖将在安装时自动解析和部署。

### Helm Upgrade

当需要更新配置或镜像版本时，使用`helm upgrade`命令：

```bash
helm upgrade smartabp ./deployment/k8s/helm/smartabp \
  --namespace smartabp \
  --set frontend.image.tag="1.1.0" \
  --set backend.image.tag="1.1.0"
```

升级操作将触发滚动更新（Rolling Update），Kubernetes会逐步替换旧的Pod实例，确保服务不中断。Helm会记录每次发布的版本，便于后续回滚。

### Helm Rollback

如果升级后出现问题，可以使用`helm rollback`命令回滚到之前的稳定版本：

```bash
# 查看发布历史
helm history smartabp --namespace smartabp

# 回滚到上一个版本
helm rollback smartabp 1 --namespace smartabp
```

回滚操作将恢复到指定版本的配置状态，包括所有资源的定义。

## 部署验证步骤

部署完成后，需要进行一系列验证以确保系统正常运行。

### 检查Pod状态

使用以下命令检查所有Pod是否处于运行状态：

```bash
kubectl get pods -n smartabp
```

所有Pod的`STATUS`应为`Running`，且`RESTARTS`为0。重点关注后端Pod的初始化容器（initContainer）是否成功完成数据库迁移。

### 服务可达性验证

验证前端和后端服务是否可通过ClusterIP访问：

```bash
# 检查服务
kubectl get svc -n smartabp

# 测试服务连通性（在集群内）
kubectl exec -it <frontend-pod> -n smartabp -- curl http://smartabp-frontend:80
kubectl exec -it <backend-pod> -n smartabp -- curl http://smartabp-backend:80/health
```

### Ingress配置验证

验证Ingress资源是否正确配置并可通过外部域名访问：

```bash
# 检查Ingress
kubectl get ingress -n smartabp

# 外部访问测试
curl -k https://lowcode.smartabp.com
curl -k https://api.lowcode.smartabp.com/health
```

Ingress配置中包含了SSL重定向、CORS策略、安全头等关键设置，确保外部访问的安全性和正确性。

### 健康检查端点

系统提供了多个健康检查端点用于验证组件状态：

- 前端健康检查：`/health`（返回200）
- 后端健康检查：`/health`（整体健康）和`/health/ready`（就绪状态）
- Nginx状态页：`/nginx_status`（需内部访问）

## 常见问题排查指南

### 镜像拉取失败

**现象**：Pod状态为`ImagePullBackOff`或`ErrImagePull`。

**解决方案**：
1. 检查镜像名称和标签是否正确
2. 确认镜像仓库可访问
3. 如果使用私有仓库，确保已配置正确的`imagePullSecrets`

```yaml
# 在values.yaml中配置
frontend:
  image:
    repository: smartabp/lowcode-frontend
    tag: "1.0.0"
  imagePullSecrets:
    - name: regcred
```

### 资源不足

**现象**：Pod因资源限制被终止或无法调度。

**解决方案**：
1. 检查Pod的资源请求和限制配置
2. 根据实际负载调整`resources`设置
3. 确保节点有足够的可用资源

```yaml
# 在values.yaml中调整资源
backend:
  resources:
    requests:
      memory: "1Gi"
      cpu: "500m"
    limits:
      memory: "2Gi"
      cpu: "1000m"
```

### 配置错误

**现象**：应用启动失败或功能异常。

**常见配置问题**：
- 数据库连接字符串错误
- Redis配置不匹配
- CORS设置不正确
- 环境变量未正确注入

**排查方法**：
1. 检查ConfigMap和Secret是否正确生成
2. 查看Pod日志确认配置加载情况
3. 验证环境变量是否正确注入

```bash
# 查看ConfigMap
kubectl get configmap -n smartabp

# 查看Secret
kubectl get secret -n smartabp

# 查看Pod环境变量
kubectl exec -it <pod-name> -n smartabp -- env
```

## CI/CD集成最佳实践

### 自动化部署流水线

建议在CI/CD流水线中集成以下步骤：

```yaml
# 示例CI/CD流程
deploy:
  stage: deploy
  script:
    # 1. 构建镜像
    - docker build -t $IMAGE_NAME:$IMAGE_TAG ./src
    # 2. 推送镜像
    - docker push $IMAGE_NAME:$IMAGE_TAG
    # 3. 更新Helm values
    - sed -i "s|tag: \".*\"|tag: \"$IMAGE_TAG\"|" values.yaml
    # 4. 执行Helm升级
    - helm upgrade --install smartabp ./helm-chart --values values.yaml
  only:
    - main
```

### 版本控制与回滚

- 将`values.yaml`文件纳入版本控制
- 为每次发布创建Git标签
- 记录Helm发布历史，便于追踪和回滚

### 安全最佳实践

1. **敏感信息管理**：使用Helm Secrets或外部密钥管理服务
2. **镜像安全**：扫描镜像漏洞，使用可信基础镜像
3. **RBAC**：启用RBAC并遵循最小权限原则
4. **网络策略**：启用网络策略限制不必要的网络通信

### 监控与告警

- 集成Prometheus和Grafana进行性能监控
- 配置健康检查和就绪探针
- 设置关键指标的告警规则（CPU、内存、请求延迟等）
