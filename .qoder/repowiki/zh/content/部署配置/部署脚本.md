## 部署流程分析

`deploy-production.sh` 脚本实现了从参数解析到健康检查的完整部署流程。脚本首先通过 `main` 函数解析部署目标参数（Docker Compose 或 Kubernetes），默认为 Docker Compose 模式。部署流程包含五个核心阶段：先决条件检查、环境变量加载、镜像构建、平台部署和健康检查。

在先决条件检查阶段，脚本验证 Docker、Docker Compose 和 kubectl（Kubernetes 部署时）的安装状态。环境变量加载阶段通过 `load_env_file` 函数读取 `.env.production` 文件，`validate_env` 函数确保关键环境变量（如数据库密码、JWT 密钥等）已正确配置。镜像构建阶段使用 `docker build` 命令基于 `Dockerfile.production` 构建应用镜像。

部署阶段根据目标平台执行不同操作：Docker Compose 模式通过 `docker-compose down` 停止旧服务，再通过 `docker-compose up -d` 启动新服务；Kubernetes 模式则通过 `kubectl apply` 应用命名空间、ConfigMap、Secret 和部署配置，并使用 `kubectl rollout status` 等待部署完成。最后，`show_deployment_info` 函数输出部署完成信息和访问指引。

## 性能优化措施

`production-optimization.sh` 脚本实施了全面的性能优化措施，涵盖前端、后端、数据库和基础设施。前端优化通过 `optimize_frontend` 函数执行，包括运行 ESLint 代码质量检查、npm 安全审计、构建分析，并生成优化的生产构建。后端优化通过 `optimize_backend` 函数实现，使用 .NET CLI 的 `dotnet publish` 命令创建针对 Linux x64 平台的优化发布，配置了发布修剪和单文件发布等参数。

脚本通过 `create_docker_configuration` 函数创建了多阶段 Docker 配置，显著提升了构建效率和安全性。Dockerfile 采用三阶段构建：第一阶段使用 .NET SDK 构建后端 API，第二阶段使用 Node.js 构建前端，第三阶段使用轻量级 ASP.NET 运行时镜像。该配置通过 `COPY --from` 指令仅复制必要的构建产物，减小了最终镜像体积。同时，脚本创建了 `docker-compose.prod.yml` 文件，定义了包含应用、数据库、Redis、Elasticsearch 和 Nginx 的完整生产环境服务栈。

JIT 编译和 GC 调优通过 .NET 发布配置实现，`/p:PublishTrimmed=false` 和 `/p:PublishSingleFile=false` 确保了最佳运行时性能。连接池配置在 Nginx 配置中通过 `upstream` 指令定义，实现了负载均衡和高可用性。

## 生产就绪检查

`production-readiness-check.sh` 脚本执行了全面的生产就绪检查，包含六个维度的验证：安全、性能、基础设施、质量、合规性和环境。安全验证检查 HTTPS 配置、安全头（X-Frame-Options, X-Content-Type-Options）、速率限制和 JWT 认证配置。性能验证确认前端代码分割、后端优化发布、数据库优化脚本和缓存配置均已就绪。

基础设施验证确保 Docker 配置、Docker Compose 文件、监控堆栈和备份策略已正确配置。质量验证检查单元测试、E2E 测试、代码质量和安全审计报告的存在。合规性验证确认审计日志、数据加密和基于角色的访问控制已启用。环境验证检查生产配置文件、密钥管理和日志配置。

脚本通过 `main` 函数协调所有验证，并生成详细的 HTML 报告 `production-readiness-report.html`。报告包含通过、警告和关键问题的统计摘要，并提供可视化的检查结果。最终，脚本根据检查结果输出总结：若无关键问题，则系统准备就绪；否则，必须解决所有关键问题才能部署。

## 使用示例与扩展方法

脚本提供了清晰的使用示例和灵活的扩展方法。`deploy-production.sh` 的基本用法为 `./deploy-production.sh [docker-compose|kubernetes]`，例如 `./deploy-production.sh kubernetes` 将执行 Kubernetes 部署。`production-optimization.sh` 可直接运行以执行所有优化步骤，或通过函数调用选择性执行特定优化，如 `optimize_frontend` 仅优化前端。

`production-readiness-check.sh` 可独立运行以评估系统状态。扩展方法包括：通过修改 `REQUIRED_VARS` 数组扩展环境变量验证；通过添加新的 `validate_*` 函数扩展检查项；通过修改 `create_docker_configuration` 函数调整 Docker 配置。脚本的模块化设计允许轻松集成新的测试套件或监控工具。

## 日志输出与错误处理

脚本实现了统一的日志输出和健壮的错误处理机制。日志函数（如 `log_info`, `log_success`, `log_error`）使用 ANSI 颜色代码输出结构化信息，便于在终端中快速识别不同级别的日志。所有日志均包含时间戳和状态标识，确保输出清晰可读。

错误处理通过 `set -e` 和 `trap` 命令实现。`set -e` 确保脚本在任何命令失败时立即退出。`trap` 命令在 `ERR` 信号触发时执行回滚操作，`rollback_deployment` 函数会根据部署目标执行相应的回滚命令（如 `kubectl rollout undo`）。这种机制保证了部署过程的原子性，避免了部分部署导致的系统不稳定。
