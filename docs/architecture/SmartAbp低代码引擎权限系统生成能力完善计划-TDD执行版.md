## 1. 第一阶段：后端代码生成引擎 (`SmartAbp.CodeGenerator`) 核心能力升级

**目标**: 扩展后端代码生成器，使其能完全理解并生成设计文档中定义的复杂实体、聚合根和业务逻辑。

### 1.1 TDD: 复杂聚合根生成器 (`ComplexAggregateRootGenerator`)
- **任务**: 开发一个新的代码生成器，专门处理具有层级结构、复杂业务属性和枚举的聚合根。
- **输入**: `OrganizationUnit` 实体元数据。
- **TDD流程**:
  1.  **红**: 编写测试，断言新生成器无法正确生成包含 `ParentId`, `HierarchyPath`, `Level` 和 `OrganizationUnitType` 枚举的 `OrganizationUnit.cs` 文件。
  2.  **绿**: 实现 `ComplexAggregateRootGenerator`，使其能解析层级关系元数据，正确生成 `Parent` 和 `Children` 导航属性、层级路径、枚举定义以及所有业务字段。
  3.  **重构**: 优化代码，将层级逻辑、枚举生成逻辑抽象为独立的子服务，方便复用。
- **验收标准**:
  - [ ] 能100%生成与设计文档 `3.1.1` 节完全一致的 `OrganizationUnit.cs`。
  - [ ] 能自动生成 `OrganizationUnitType`, `OrganizationStatus`, `DataScope` 等所有相关枚举。
  - [ ] 为 `HierarchyPath` 和 `Code` 字段自动生成唯一的索引配置。

### 1.2 TDD: 关联实体生成器 (`AssociationEntityGenerator`)
- **任务**: 增强代码生成器，使其能够处理多对多关联实体，如 `OrganizationUser` 和 `OrganizationRole`。
- **输入**: `OrganizationUser` 实体元数据及其与 `OrganizationUnit` 和 `AppUser` 的关系。
- **TDD流程**:
  1.  **红**: 编写测试，断言现有生成器无法创建 `OrganizationUser.cs` 并正确配置其在 `DbContext` 中的复合主键和外键关系。
  2.  **绿**: 实现 `AssociationEntityGenerator`，使其能识别多对多关系，生成关联实体类，并在 `DbContext` 中使用 `HasKey(t => new { t.OrganizationUnitId, t.UserId })` 配置复合主键。
  3.  **重构**: 将 `DbContext` 配置逻辑模块化。
- **验收标准**:
  - [ ] 能100%生成与设计文档 `3.1.2` 和 `3.1.3` 节完全一致的 `OrganizationUser.cs` 和 `OrganizationRole.cs`。
  - [ ] 自动在 `SmartAbpDbContext.cs` 中添加正确的 `OnModelCreating` 配置。

### 1.3 TDD: 数据权限逻辑注入器 (`DataPermissionInjector`)
- **任务**: 开发一个代码注入器，在生成的应用服务和仓储中自动应用数据权限过滤逻辑。
- **输入**: DTO元数据和 `DataScope` 枚举。
- **TDD流程**:
  1.  **红**: 编写测试，断言生成的 `OrganizationUnitAppService` 的 `GetListAsync` 方法没有根据当前用户的 `DataScope` 进行数据过滤。
  2.  **绿**: 实现 `DataPermissionInjector`，通过Roslyn AST分析和修改生成的服务代码，在查询方法中注入基于 `ICurrentUser` 和 `IDataPermissionEngine` 的过滤代码，类似文档 `7.4` 节的设计。
  3.  **重构**: 将不同的数据权限过滤策略（如`OrganizationAndChildren`）抽象为策略模式。
- **验收标准**:
  - [ ] 生成的应用服务列表查询方法中包含数据权限过滤代码。
  - [ ] 自动在仓储接口中扩展支持数据权限的查询方法。

## 2. 第二阶段：前端低代码引擎 (`@smartabp/lowcode-*`) 核心能力突破

**目标**: 彻底重构和增强前端低代码引擎，特别是可视化设计器和代码生成器，以支持权限系统所需的高级UI模式。

### 2.1 TDD: 核心元数据扩展 (`@smartabp/lowcode-core`)
- **任务**: 扩展元数据定义，使其能描述树形结构、权限矩阵和高级搜索。
- **TDD流程**:
  1.  **红**: 编写测试，断言当前的元数据结构无法描述一个字段是“树节点的父ID”或一个组件是“权限矩阵”。
  2.  **绿**: 扩展元数据JSON Schema，增加 `isTreeParentKey`, `hierarchyPathField` 等属性，并新增 `uiType: 'PermissionMatrix'` 等元类型。
  3.  **重构**: 优化元数据解析服务，提高性能。
- **验收标准**:
  - [ ] 元数据标准能够完整描述 `OrganizationUnit` 的树形结构。
  - [ ] 元数据标准能够定义一个包含角色轴和权限轴的权限矩阵。

### 2.2 TDD: 可视化设计器革命 (`@smartabp/lowcode-designer`)
- **任务**: 开发全新的可视化设计组件以支持权限管理界面的设计。
- **2.2.1 树形视图设计器 (`Tree View Designer`)**:
  - **TDD流程**:
    1.  **红**: 编写Vitest UI测试，模拟用户拖拽一个“组织树”组件到画布上，断言失败。
    2.  **绿**: 开发 `TreeView` 设计时组件，允许用户通过拖拽绑定数据源，并在属性面板中配置 `ParentId` 字段、`Display` 字段等。
    3.  **重构**: 抽象出通用的数据驱动设计组件基类。
- **2.2.2 权限矩阵设计器 (`Permission Matrix Designer`)**:
  - **TDD流程**:
    1.  **红**: 编写UI测试，尝试设计一个角色为行、权限为列的矩阵，断言失败。
    2.  **绿**: 开发 `PermissionMatrix` 设计时组件，允许绑定角色数据源和权限数据源，并能配置交叉点的权限状态（允许/拒绝/继承）。
    3.  **重构**: 将矩阵的行列渲染逻辑解耦。
- **验收标准**:
  - [ ] 设计器中提供可用的“组织树”和“权限矩阵”组件。
  - [ ] 用户可以通过可视化方式设计出与文档 `5.1.1` 和 `5.3.2` 节完全一致的界面布局。

### 2.3 TDD: 前端代码生成器升级 (`@smartabp/lowcode-codegen`)
- **任务**: 开发新的Vue模板和生成逻辑来渲染由新设计器创建的复杂界面。
- **2.3.1 树形管理页面模板**:
  - **TDD流程**:
    1.  **红**: 编写测试，使用包含树形视图的元数据进行代码生成，断言生成的Vue文件缺少 `ElTree` 组件和相应的API调用。
    2.  **绿**: 创建 `TreeManagement.template.vue`，实现左侧为树、右侧为详情的经典布局。生成器根据元数据填充API调用、字段绑定等。
    3.  **重构**: 优化模板，使其更具可配置性。
- **2.3.2 权限矩阵页面模板**:
  - **TDD流程**:
    1.  **红**: 编写测试，使用权限矩阵元数据进行生成，断言生成的代码无法渲染出矩阵。
    2.  **绿**: 创建 `PermissionMatrix.template.vue`，使用 `ElTable` 或CSS Grid动态生成矩阵，并处理复杂的勾选和状态变更逻辑。
    3.  **重构**: 将权限计算和状态管理的逻辑抽离到 Pinia Store 中，模板只负责渲染。
- **验收标准**:
  - [ ] 能够100%生成功能完备、布局正确的组织管理和权限矩阵页面。
  - [ ] 生成的 Pinia Store 包含处理树形数据加载和权限矩阵状态管理的逻辑。

## 3. 第三阶段：端到端（E2E）生成与验证

**目标**: 使用升级后的全栈低代码引擎，完整生成整个权限管理系统，并通过自动化E2E测试验证其功能完备性。

### 3.1 E2E TDD: 组织管理模块生成
- **任务**: 从元数据开始，一键生成组织管理模块的所有前后端代码。
- **TDD流程 (Cypress)**:
  1.  **红**: 编写Cypress测试脚本，覆盖“新增组织”、“拖拽移动部门”、“为部门分配员工”等场景，断言所有测试失败。
  2.  **绿**:
     - 使用 **阶段一** 升级的后端引擎生成所有组织相关的实体、服务和API。
     - 使用 **阶段二** 升级的前端引擎设计并生成组织管理的UI界面。
     - 部署并运行生成的代码，直到所有Cypress测试通过。
  3.  **重构**: 优化生成的代码，提高性能和可读性。
- **验收标准**:
  - [ ] 成功生成组织管理模块的所有前后端代码。
  - [ ] 所有相关Cypress测试用例100%通过。

### 3.2 E2E TDD: 角色与权限矩阵模块生成
- **任务**: 一键生成角色管理和权限矩阵模块的所有代码。
- **TDD流程 (Cypress)**:
  1.  **红**: 编写Cypress测试，覆盖“创建角色”、“在矩阵中为角色授权”、“对比角色权限差异”等核心场景，断言失败。
  2.  **绿**:
     - 生成后端角色、权限相关的代码。
     - 设计并生成前端角色列表及权限矩阵界面。
     - 部署运行，修复问题直至测试通过。
  3.  **重构**: 优化权限矩阵组件的渲染性能。
- **验收标准**:
  - [ ] 成功生成角色与权限管理模块的代码。
  - [ ] 所有相关Cypress测试用例100%通过。

## 4. 第四阶段：企业级特性生成能力集成

**目标**: 为低代码引擎增加生成高级企业级特性的能力，解决“D爷级别核心问题”。

### 4.1 TDD: 智能缓存代码生成
- **任务**: 让引擎在生成服务时，能自动添加对多级缓存的支持。
- **验收标准**: [ ] 生成的应用服务自动包含对 `PermissionPrewarmService` 的调用和缓存失效逻辑。

### 4.2 TDD: Elasticsearch审计日志生成
- **任务**: 引擎在生成 `AppService` 的增删改方法时，自动注入向ES写入结构化审计日志的代码。
- **验收标准**: [ ] 生成的CUD操作方法包含调用 `ElasticsearchAuditLogStore` 的代码。

### 4.3 TDD: 灰度发布与回滚API生成
- **任务**: 引擎能够生成支持权限变更灰度发布和版本回滚的管理API。
- **验收标准**: [ ] 自动生成 `PermissionGrayReleaseService` 及其API控制器。

---

**最终交付**: 一个全面升级、经过TDD严格验证的全栈低代码引擎，能够根据《2025企业级后台权限管理系统详细设计说明书》的元数据，**一键生成一个功能完整、性能卓越、安全可靠的企业级权限管理系统**。
