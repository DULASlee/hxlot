# ADR-0009: 增量代码生成实现

- **状态**: 已实现
- **日期**: 2025-09-29
- **决策者**: 首席架构师
- **标签**: 代码生成, 性能优化, 增量更新

## 背景

SmartAbp低代码引擎在实际使用中面临以下代码生成性能问题：

1. **全量生成耗时过长**: 每次生成都重新生成所有文件，即使只有一个字段描述发生变更
2. **开发体验差**: 大型项目生成时间长达数分钟，影响开发效率
3. **资源浪费**: 重复生成未变更的文件消耗大量CPU和磁盘IO
4. **缓存机制缺失**: 没有智能缓存机制识别哪些文件需要重新生成

## 决策

实施智能增量代码生成机制，基于输入变更检测决定是否重新生成特定文件。

### 核心技术方案

#### 1. 输入哈希计算 (InputHashCalculator)
- **技术**: SHA-256哈希算法
- **输入范围**: 模板文件内容 + JSON元数据 + 配置文件
- **哈希稳定性**: 相同输入始终产生相同哈希值
- **组合哈希**: 支持多输入组合哈希计算

```csharp
// 核心哈希计算实现
public string ComputeStringHash(string content)
{
    using var sha256 = SHA256.Create();
    var bytes = Encoding.UTF8.GetBytes(content);
    var hashBytes = sha256.ComputeHash(bytes);
    return Convert.ToHexString(hashBytes).ToLowerInvariant();
}
```

#### 2. 状态缓存管理 (GenerationStateManager)
- **存储格式**: JSON文件 `generation-manifest.json`
- **存储位置**: `.generated` 目录根目录
- **状态内容**: 输入哈希字典、生成文件列表、时间戳、元数据
- **备份机制**: 支持状态备份和恢复

```json
{
  "generationId": "abc123...",
  "timestamp": "2025-09-29T10:30:00Z",
  "inputHashes": {
    "template:Entity.cs.template": "a1b2c3...",
    "metadata:primary": "d4e5f6...",
    "config:primary": "g7h8i9..."
  },
  "generatedFiles": [
    "UserEntity.cs",
    "UserAppService.cs",
    "UserDto.cs"
  ]
}
```

#### 3. 增量生成引擎 (IncrementalGenerationEngine)
- **变更检测**: 对比当前输入哈希与上次缓存哈希
- **智能跳过**: 无变更时完全跳过生成过程
- **增量更新**: 只重新生成变更相关的文件
- **错误恢复**: 完整的异常处理和状态恢复

#### 4. 集成到现有管道 (StableGenerationPipeline)
- **兼容性**: 扩展现有请求结构，添加增量模式支持
- **向后兼容**: 不影响现有全量生成功能
- **渐进迁移**: 可选择性启用增量模式

### 增量逻辑流程

```
1. 加载上次生成状态 (generation-manifest.json)
2. 分析当前输入 (模板 + 元数据 + 配置)
3. 计算当前输入哈希值
4. 对比哈希变更:
   - 无变更 → 跳过生成
   - 有变更 → 执行增量生成
5. 更新生成状态缓存
```

## 性能预期

### 性能提升指标

| 场景 | 全量生成时间 | 增量生成时间 | 性能提升 |
|------|-------------|-------------|----------|
| 无变更重新生成 | 30秒 | <1秒 | 30x |
| 单字段描述修改 | 30秒 | 3-5秒 | 6-10x |
| 单模板文件修改 | 30秒 | 5-10秒 | 3-6x |
| 大型项目 (50+ 实体) | 300秒 | 10-30秒 | 10-30x |

### 资源使用优化

- **CPU使用**: 减少80-95%的重复计算
- **磁盘IO**: 减少90%的文件写入操作
- **内存占用**: 状态缓存仅占用几KB内存
- **开发体验**: 大幅缩短等待时间，提升开发效率

## 验收标准

### 功能验收

1. **首次生成**: 
   - [ ] 行为与原全量生成完全一致
   - [ ] 生成状态文件正确创建

2. **无变更重新生成**:
   - [ ] 检测到无变更，跳过生成
   - [ ] 耗时 < 1秒
   - [ ] 日志显示 "无变更检测到，跳过代码生成"

3. **增量变更生成**:
   - [ ] 修改实体字段描述，只有相关文件重新生成
   - [ ] 未变更的文件保持原有时间戳
   - [ ] 生成状态正确更新

4. **状态管理**:
   - [ ] 状态文件格式正确且可读
   - [ ] 支持状态备份和恢复
   - [ ] 状态文件损坏时自动重新开始

### 性能验收

1. **响应时间**:
   - [ ] 无变更场景 < 1秒
   - [ ] 增量变更场景比全量生成至少快3倍

2. **资源使用**:
   - [ ] 状态文件大小 < 1MB
   - [ ] 内存使用增量 < 10MB

## 风险和缓解

### 已识别风险

1. **哈希冲突风险**
   - **概率**: 极低 (SHA-256冲突概率 < 2^-128)
   - **影响**: 可能错误跳过生成
   - **缓解**: 使用业界标准SHA-256算法

2. **状态文件损坏**
   - **概率**: 低
   - **影响**: 需要重新全量生成
   - **缓解**: 自动检测并恢复，支持备份机制

3. **复杂依赖关系**
   - **概率**: 中
   - **影响**: 可能遗漏需要重新生成的文件
   - **缓解**: 保守策略，有依赖变更时重新生成相关文件

### 回退方案

- **功能开关**: 支持禁用增量模式，回退到全量生成
- **清除缓存**: 提供缓存清除接口，强制全量重新生成
- **向后兼容**: 不影响现有代码生成功能

## 结论

增量代码生成机制的实施将显著提升SmartAbp低代码引擎的开发效率和用户体验。通过智能的变更检测和状态缓存，预期可实现3-30倍的性能提升，特别是在无变更重新生成场景下可达到30倍以上的性能改进。

该方案采用成熟稳定的技术栈，具有良好的可扩展性和向后兼容性，风险可控，建议优先实施。
