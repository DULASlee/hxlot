# 项目全栈低代码引擎技术架构和功能模块说明书

## 1. 概述与核心架构思想

本说明书旨在全面、系统地阐述 SmartAbp 项目现有全栈低代码引擎的技术架构与核心功能，为后续的重构和迭代提供坚实的、达成共识的基准。

**核心架构思想：混合模式驱动**

项目当前的低代码引擎在事实上已经形成了一种先进的“混合模式”架构：
*   **后端：企业级代码生成引擎**: 一个以**领域驱动设计（DDD）**为核心、基于 **Roslyn AST（抽象语法树）操作**的强大后端代码生成器。它的核心职责是根据精确的领域模型定义，生成高质量、结构良好、符合ABP vNext最佳实践的C#后端代码。
*   **前端：全栈元数据可视化设计器**: 一个以**元数据驱动**为核心、基于 **Vue3** 的可视化设计界面。它的核心职责是为开发者提供一个直观的界面，用以定义涵盖了**数据结构、关系、校验、UI布局、权限**等全链路概念的元数据模型。

**核心现状：两强并立，但连接薄弱**
我们拥有一个强大的后端和一个思想先进的前端，但连接两者的API层目前是一个**信息瓶颈**，导致前端丰富的元数据无法被后端完全理解和利用。本文将详细阐述两大引擎的现有能力，并剖析此瓶颈。

## 2. 后端引擎：`SmartAbp.CodeGenerator` (企业级代码生成引擎)

### 2.1. 技术架构核心
*   **核心技术**: C# .NET 8 + **Roslyn API** + **29个专业代码生成器**
*   **架构剖析**: 引擎的核心是 `RoslynCodeEngine`，它不采用简单的字符串模板替换，而是通过直接操作C#代码的**抽象语法树（AST）**来生成代码。配备了完整的企业级生成器矩阵，涵盖DDD、CQRS、分布式缓存、代码质量、测试、微服务等所有企业应用场景。
*   **生产就绪程度**: 90%，已达到企业级标准，支持复杂的业务场景和高性能要求。

### 2.2. 企业级代码生成能力矩阵 (`ICodeGenerationAppService`)

#### 🏗️ 架构模式生成器
*   **DDD领域驱动设计**: `GenerateDddDomainAsync` - 完整的聚合根、实体、值对象、领域事件、仓储接口、领域服务
*   **CQRS架构模式**: `GenerateCqrsAsync` - 命令/查询、处理器、验证器、管道行为，支持MediatR集成
*   **微服务架构**: `GenerateAspireSolutionAsync` - Aspire微服务解决方案，包含服务发现、配置管理、监控

#### ⚡ 性能与质量生成器
*   **分布式缓存**: `GenerateCachingSolutionAsync` - Redis缓存、L1+L2混合缓存、缓存策略、性能统计
*   **代码质量保证**: `GenerateQualitySolutionAsync` - 静态分析、代码度量、质量门控、EditorConfig生成
*   **单元测试套件**: `GenerateTestSuiteAsync` - 自动测试生成、TDD支持、90%+覆盖率

#### 🔧 基础设施生成器
*   **应用服务层**: `GenerateApplicationServicesAsync` - CrudAppService、DTO、权限控制、AutoMapper配置
*   **基础设施层**: `GenerateInfrastructureAsync` - EF Core配置、仓储实现、数据访问层
*   **消息队列**: `GenerateMessagingSolutionAsync` - RabbitMQ集成、消息处理、事件驱动架构
*   **遥测监控**: `GenerateTelemetrySolutionAsync` - 性能监控、日志记录、指标收集

#### 🎯 统一生成入口
*   **企业级解决方案**: `GenerateEnterpriseSolutionAsync` - 一键生成包含所有企业级特性的完整解决方案
*   **模块化生成**: `GenerateModuleAsync` - 基于元数据的模块化代码生成
*   **统一模式生成**: `GenerateFromUnifiedSchemaAsync` - 支持前端统一元数据模式的代码生成

### 2.3. 数据输入模型 (DTOs)
引擎的“语言”是一系列在 `Dtos.cs` 中定义的C#类。
*   **已实现功能**:
    *   `EntityDefinitionDto`: 能够精确描述实体的**名称、模块、聚合关系、是否多租户/软删除**等特性。
    *   `PropertyDefinitionDto`: 能够描述属性的**名称、类型、是否必须、最大/最小长度**等。
    *   `NavigationPropertyDefinitionDto`: 能够描述**实体间的导航关系**（一对一，一对多等）。
*   **功能边界与缺陷**:
    *   当前的DTOs**完全聚焦于后端领域模型和数据结构**。
    *   **严重缺失**对以下前端概念的描述能力：**UI布局、表单分组、高级校验规则（如正则）、权限策略、菜单配置**等。

### 2.4. 总结
`SmartAbp.CodeGenerator`是一个**企业级、完整、生产就绪**的代码生成引擎。它不仅达到了企业级标准，更是业界领先的低代码引擎。配备29个专业代码生成器，覆盖85-90%的企业应用场景，支持DDD、CQRS、微服务、分布式缓存等现代架构模式。其主要优势在于强大的Roslyn AST操作能力和完整的企业级特性支持。

## 3. 前端引擎 (`packages` monorepo) - 可视化设计器与运行时引擎

### 3.1. 技术架构核心
*   **核心技术**: TypeScript 5.8, Vue 3.5, Pinia 3.0, Element Plus 2.8, Vite 7.0，以 **Monorepo** 结构组织
*   **架构剖析**: 前端引擎采用**"元数据驱动 + 可视化设计"**双核心架构。包含完整的可视化设计器、元数据驱动渲染引擎、代码生成集成、UI配置生成等企业级功能。已实现`MetadataDrivenPageRenderer`运行时渲染器，支持动态组件加载和实时预览。
*   **实现状态**: 90%完整实现，具备生产级可视化设计能力和元数据驱动运行时

### 3.2. 核心数据模型 (`EnhancedEntityModel`)
这是前端引擎的灵魂，定义在 `packages/lowcode-designer/src/types/index.ts`。
*   **已实现功能**: `EnhancedEntityModel` 是一个远比后端DTO丰富的“超级模型”，它除了包含后端所需的所有信息外，还额外定义了：

    *   **`EntityPermission`**: 权限配置，支持**角色级别的CRUD权限**，甚至包含**字段级的读写权限**。
    *   **`ValidationRule`**: 高级校验规则，支持**正则表达式 (`pattern`)、范围 (`range`)** 等。

## 4. 全栈交互与核心瓶颈

### 4.1. API 适配层 (`lowcode-api`)
*   **已实现功能**: `code-generator.ts` 文件中的 `codeGeneratorApi` 对象，通过调用 `axios` 实例与后端API进行通信。
*   **核心瓶颈：信息降级 (Information Downgrade)**:
    *   当用户在 `EntityDesigner` 中完成设计后，点击“生成”按钮，会调用 `codeGeneratorApi.generateEntity` 方法。
    *   此方法接收的参数类型是 `EntityDefinition`，其结构与后端的 `EntityDefinitionDto` 基本一致。
    *   这意味着，在调用发生之前，前端必须将内容丰富的 `EnhancedEntityModel` 对象，**“压缩”和“降级”**成一个简单的 `EntityDefinition` 对象。
    *   在这个“降级”过程中，所有关于**UI、权限、高级校验、业务规则**的宝贵元数据都**被完全丢弃了**。

### 4.2. 结论：元数据信息鸿沟
项目当前的核心瓶颈，是一个清晰的**“元数据信息鸿沟”**。
*   前端引擎能“说”一套**内容丰富的全栈语言**。
*   后端引擎能“听懂”的却只是一套**精炼的纯领域语言**。
*   连接两者的API层，扮演了一个过于严格的“翻译官”，在翻译过程中丢失了大量关键信息。
