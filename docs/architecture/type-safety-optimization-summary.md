## 💡 技术创新

### 1. 类型系统架构

```typescript
// 分层的类型定义
global.d.ts (全局扩展)
    ├─ Window/globalThis扩展
    ├─ SmartAbpGlobal配置
    └─ 动态导入类型

entity.ts (领域实体)
    ├─ BaseEntity
    ├─ MasterEntity
    └─ DetailEntity

service-discovery/types.ts (服务发现)
    ├─ ConsulServiceResponse
    ├─ EurekaServiceResponse
    └─ ServiceInstance
```

### 2. Function构造器动态导入

```typescript
// 创新点：绕过TypeScript限制，保持类型安全
const dynamicImport = new Function(
  'path', 
  'return import(path)'
) as DynamicImport

const module = await dynamicImport(metadata.path)
```

### 3. unknown vs any的选择

```typescript
// ✅ 更安全的方式
export interface ViteModule {
  default?: unknown  // 而非any
  [key: string]: unknown
}

// 调用者必须进行类型检查
const component = module.default as Component
```

## 📚 最佳实践总结

### DO ✅

1. **优先使用unknown而非any**
   - 强制类型检查
   - 更明确的意图

2. **建立类型系统而非零散定义**
   - 集中管理
   - 便于维护

3. **使用泛型约束**
   - 提升类型推断
   - 减少类型断言

4. **添加详细注释**
   - 说明设计意图
   - 记录技术决策

### DON'T ❌

1. **不要盲目追求零as any**
   - 某些场景as any是合理的
   - 权衡复杂度和收益

2. **不要使用@ts-ignore**
   - 100%可以找到类型安全替代方案
   - 必要时使用as any而非@ts-ignore

3. **不要过度复杂的类型**
   - 可维护性优于完美类型
   - 实用主义而非理想主义
