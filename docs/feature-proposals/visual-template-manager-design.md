# 可视化模板管理界面 - 设计与规划文档

**版本**: 1.0
**状态**: 草案

## 1. 目标与愿景

### 1.1. 核心目标
- **提升开发效率**: 将模板的发现、配置和应用过程从命令行操作转变为可视化、一站式的流畅体验。
- **降低使用门槛**: 使开发者无需记忆模板ID和复杂的CLI命令，即可轻松使用模板库。
- **增强模板可见性**: 提供一个集中的“模板市场”，让开发者可以轻松浏览、搜索和了解所有可用的模板。
- **保证规范执行**: 通过UI引导，确保模板参数被正确填写，从源头上保证生成代码的规范性。

### 1.2. 最终愿景
将模板管理界面打造为低代码设计器中的一个核心功能，使其成为项目代码初始化的“启动面板”，实现真正的“代码生成即服务”。

## 2. 核心功能设计

### 2.1. 模板市场 (Template Marketplace)
- **视图**: 采用卡片式或列表式布局，展示所有可用的代码模板。
- **信息展示**: 每个卡片清晰展示模板的 `name`, `description`, `tags`, `version` 和 `author`。
- **搜索功能**: 提供一个实时搜索框，可根据模板名称、描述或标签进行快速过滤。
- **分类与过滤**: 提供基于`tags`（如 `frontend`, `backend`, `crud`, `store`）的分类筛选功能。

### 2.2. 模板详情与配置 (Template Detail & Configuration)
- **触发**: 点击模板市场中的任意卡片，会进入该模板的详情与配置界面。
- **详细信息**: 展示模板 `template.json` 中的所有元数据。
- **动态表单**: 根据模板的 `placeholders` 数组，自动生成一个配置表单。
  - 每个占位符对应一个表单输入项。
  - 输入项的标签为占位符的 `name`，并附带 `description` 作为提示信息。
  - 自动应用 `defaultValue`。
  - 根据 `required` 属性进行表单校验。
- **输出路径配置**: 提供一个输入框或目录选择器，用于指定生成代码的目标路径（相对于项目根目录）。
- **代码预览 (可选)**: 提供一个只读的代码预览窗口，展示模板文件应用了默认值后的样子，帮助开发者理解模板效果。

### 2.3. 一键生成 (One-Click Generation)
- **触发**: 在配置表单填写完毕后，点击“生成代码”按钮。
- **后台操作**:
  1. UI收集所有表单数据，构建成一个JSON对象。
  2. UI根据当前选择的模板ID、配置的输出路径和构建的JSON对象，组装成一个完整的非交互式CLI命令。
     ```bash
     node scripts/templates/apply-template.js --templateId <id> --outputPath <path> --placeholders '<json_string>'
     ```
  3. UI执行此命令。
- **结果反馈**:
  - 在界面上实时显示CLI的输出日志，包括成功创建的文件列表。
  - 如果命令执行出错，显示详细的错误信息。
  - 成功后，提供一个“完成”或“返回市场”的按钮。

## 3. 技术实现草案

### 3.1. 前端实现
- **技术栈**: Vue 3, TypeScript, Element Plus。
- **集成点**: 作为低代码设计器的一个新视图/模块进行开发。
- **数据获取**:
  - **方案A (推荐)**: 增强 `npm run template:index` 脚本，使其生成一个包含所有模板元数据聚合的 `templates/index.json` 文件。前端UI启动时，只需请求这一个文件即可获取完整的模板列表。
  - **方案B**: 前端在启动时通过特定API（需要后端支持）获取文件列表，然后逐个读取 `template.json` 文件。此方案较为复杂，IO开销大。
- **组件结构**:
  - `TemplateMarketplace.vue`: 主视图，包含搜索、过滤和模板列表展示。
  - `TemplateCard.vue`: 单个模板的卡片展示组件。
  - `TemplateConfiguration.vue`: 模板详情、动态配置表单和生成逻辑的视图。

### 3.2. CLI执行与集成
这是技术上的关键挑战：**如何让运行在浏览器环境中的前端UI安全地执行本地的Node.js脚本？**

- **方案1: Electron环境 (如果设计器是桌面应用)**
  - 这是最直接的方案。在Electron的主进程中，可以使用Node.js的 `child_process.exec` 或 `spawn` 方法来直接执行CLI命令。渲染进程通过IPC与主进程通信来触发命令并接收结果。
- **方案2: 本地服务代理 (如果设计器是纯Web应用)**
  - 需要在本地运行一个轻量级的Node.js/Express服务器。
  - 前端UI通过HTTP请求将要执行的命令发送给这个本地服务器。
  - 本地服务器接收到请求后，执行相应的shell命令，并将结果通过HTTP响应返回给前端。
  - **安全考量**: 该服务器必须进行安全加固，例如只允许执行白名单中的特定命令 (`node scripts/templates/apply-template.js ...`)，防止任意命令注入。

## 4. 开发路线图 (Roadmap)

### 阶段一: 基础功能实现 (MVP)
1.  **任务1.1**: 实现 `template:index` 脚本，生成 `templates/index.json` 聚合文件。
2.  **任务1.2**: 开发 `TemplateMarketplace.vue` 组件，实现模板的列表展示、搜索和过滤功能。
3.  **任务1.3**: 开发 `TemplateConfiguration.vue` 组件，实现动态表单生成和参数填写。
4.  **任务1.4**: 实现核心的代码生成逻辑（选择一个CLI集成方案并完成）。

### 阶段二: 体验优化与增强
1.  **任务2.1**: 完善UI/UX，优化表单交互和结果反馈。
2.  **任务2.2**: (可选) 实现代码预览功能。
3.  **任务2.3**: 增加更详细的错误处理和用户引导。

### 阶段三: 深度集成
1.  **任务3.1**: 将该功能无缝嵌入到低代码设计器的整体工作流中。
2.  **任务3.2**: 探索从设计器的画布或元数据中自动提取参数，预填充到模板表单中，实现更深度的智能化。
