## 错误类型与整改方案

### 1) 导出/导入不匹配（TS2614, TS2307）
- 症状：Module has no exported member / Cannot find module
- 快速定位：`npx vue-tsc | sed -n '1,200p'`，或 IDE Problems 面板
- 根因：包入口未导出、SFC 默认导出被误用为具名导出、别名/相对路径失配
- 修复步骤：
  1. 统一从 `package/src/index.ts` 集中导出对外 API（stores/types/components）
  2. SFC 使用“先 import、后具名导出”模式
  3. `tsconfig.app.json` 保证 `@smartabp/*` paths 存在
  4. 缺失模块建 `types.ts` 占位或更正引用路径
- 示例（SFC 导出）：
```ts
// Before
export { default as CodeGenerationWizard } from './src/components/CodeGenerationWizard.vue'

// After
import CodeGenerationWizard from './src/components/CodeGenerationWizard.vue'
export { CodeGenerationWizard }
```
- 验证：重新编译上游引用（如 `lowcode-designer`），`vue-tsc` 不再报 TS2614/TS2307
- 审查清单：
  - 入口是否完整导出？
  - 是否存在跨包相对路径？
  - SFC 是否误用具名导出默认值？

### 2) `string | undefined` 赋值到 `string`（TS2322, TS2345）
- 症状：将 `string | undefined` 传入 `string`
- 快速定位：`vue-tsc` 报错行；关注动态赋值/传参位置
- 修复步骤：
  1. 所有传参统一 `String(x ?? '')`
  2. Map/Record 取值前提供空串或默认值
  3. 正则分组访问 `match[1]` 时兜底：`match ? match[1] ?? '' : ''`
- 示例：
```ts
// Before
updateVar('--theme-brand-primary', value)

// After
updateVar('--theme-brand-primary', String(value ?? ''))
```
- 验证：变更处不再出现 TS2322/TS2345；功能无回归
- 审查清单：是否遗漏了字符串拼接、模板字面量中的可空值？

### 3) 可能为 undefined（TS2532, TS18048）
- 症状：`Object is possibly 'undefined'`
- 快速定位：`vue-tsc` 行号；常发生在 emit、数组访问、store 读取
- 修复步骤：
  1. 事件前取 `const id = obj?.id; if (!id) return`
  2. 索引前做范围检测 `if (i < 0 || i >= arr.length) return`
  3. 计算属性/onMounted 初始数据判空
- 示例（事件 emit 防护）：
```ts
const id = props.selectedComponent?.id
if (!id) return
emit('eventChange', id, eventBindings.value)
```
- 验证：TS2532 消除，操作路径具备空态兼容
- 审查清单：数组 `splice/at`/`[i]` 是否均做了边界检查？

### 4) 同名类型来源不一致（TS2719）
- 症状：同名类型被认为互不相关
- 快速定位：错误多发生在复制/返回对象类型与定义出处不一致时
- 修复步骤：统一从单一 `types` 入口导入（如 `../types/designer`）；必要时 `as` 收敛到同一声明
- 验证：TS2719 消除，类型一致
- 审查清单：是否有多处重复的类型声明/桶文件冲突？

### 5) WeakRef 不可用 / 类型缺失（TS2304）
- 症状：Cannot find name 'WeakRef'
- 根因：目标环境/TS lib 未包含 WeakRef 定义
- 修复步骤：
  1. 文件头添加 `/// <reference lib="dom" />`
  2. 封装 `createWeakRef`：有原生用原生；否则返回 `{ deref: () => target }`
  3. 存储容器使用 `any`（规避直接依赖 WeakRef 类型）
- 示例：
```ts
const hasWeakRef = typeof (globalThis as any).WeakRef !== 'undefined'
const wr: any = hasWeakRef ? new (WeakRef as any)(target) : { deref: () => target }
```
- 验证：TS2304 消除；功能一致

### 6) Web/SSR 环境差异与 Worker 保护
- 症状：`navigator` 未定义、`worker` 为 undefined、平均除零
- 修复步骤：
  1. `const cores = (typeof navigator !== 'undefined' && navigator.hardwareConcurrency) ? ... : 4`
  2. 从池取 worker 先判空；消息通道加超时与错误回调
  3. `avgTime = files.length > 0 ? total / files.length : 0`
- 验证：Node/SSR 编译通过；Worker 并发稳定

### 7) 自动发现与字符串安全
- 症状：字符串/哈希字段可空导致传参失败
- 修复步骤：
  1. 对外部输入统一 `String(x ?? '')`
  2. `extractComponentName` 对 `split().pop()` 做空值保护
  3. 传递结构 `{ path: String(filePath), content: String(fileContent) }`
- 验证：扫描/注册阶段不再出现可空传参错误

### 8) 依赖守卫/类型守卫的 undefined 入参
- 症状：`string | undefined` 作为路径/包名继续传递
- 修复步骤：
  1. `String(violation.to)`、`const target = importPath.split('/')[1] || ''`
  2. `const importPath = match[1] || ''`
  3. 非法/空目标直接返回 `null`
- 验证：守卫脚本运行稳定，不误报、不抛错

### 9) Element Plus 联合类型与样式 union
- 症状：`No overload matches this call`/联合类型不匹配
- 修复步骤：
  1. 以类型别名声明允许值集合并收敛
  2. 对样式 `position` 显式断言 `'fixed' | 'absolute' | 'relative'`
- 验证：UI 参数合法，编译通过

### 10) DevTools 面板的弱类型 API
- 症状：不存在的方法/属性导致 TS 报错
- 修复步骤：
  1. `const mgr: any = globalPluginManager as any`
  2. `mgr.getAllPlugins?.()`、`await mgr.enable?.(id)`、`await mgr.disable?.(id)`
  3. 展示字段兜底：`(comp as any).path || '-'`
- 验证：面板渲染与交互正常；类型检查通过
