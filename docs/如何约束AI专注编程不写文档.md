# 🎯 如何约束AI专注编程，不写冗长文档

## 📋 文档说明

**创建日期**: 2025-10-08
**核心目标**: 解决AI大模型过度文档化、功能实现不完整的问题
**适用对象**: 所有使用AI编程助手的开发者

---

## 🚨 问题背景

### 当前AI的五大问题

```yaml
1. 过度文档化:
   - 用户要求"实现功能" → AI写10页分析报告
   - 花80%算力写文档，20%算力写代码
   - 本末倒置

2. 需求分析不足:
   - 不深入理解真实需求
   - 不搜索现有实现
   - 重复造轮子

3. 功能实现不完整:
   - 只写UI，不写API
   - 使用Mock数据
   - TODO占位符到处都是

4. 企业级标准缺失:
   - as any到处飞
   - 硬编码业务数据
   - 不处理错误

5. 最佳实践忽略:
   - 不参考业界方案
   - 不使用项目模板
   - 代码质量低于标准
```

---

## ✅ 解决方案

### 方案1：最高优先级规则文件（已实施）

**文件位置**: `.cursor/rules/00_AI编程禁令-专注代码不写文档.mdc`

**核心特性**:
```yaml
优先级: -1（最高，覆盖所有其他规则）
自动应用: true
```

3. **企业级标准原则**: 类型安全、真实实现、错误处理
4. **DRY原则**: 强制检索、强制模板
5. **质量标准原则**: 代码质量≥95分

## 📚 常见问题

### Q1: AI还是写了很多文档怎么办？

**回答**: 直接说："不要写文档，直接编程"或"执行AI编程禁令"

### Q2: 如何确保功能真实可用？

**回答**: 检查以下几点：
- 点击按钮是否有真实响应（不是console.log）
- 数据是否从真实API加载（不是硬编码）
- 提交表单是否真实保存（不是Mock数据）
- 刷新页面数据是否持久存在

### Q3: 如何检查代码质量？

**回答**: 要求AI执行质量检查：
```bash
# TypeScript检查
cd src/SmartAbp.Vue && npm run type-check

# ESLint检查
cd src/SmartAbp.Vue && npm run lint

# 架构合规检查
grep -r "as any\|@ts-ignore" src/
```

### Q4: 什么时候可以写文档？

**回答**: 只有用户明确要求时：
- "分析XXX架构"
- "写一份XXX设计方案"
- "生成XXX技术文档"

### Q5: 如何验证新规则是否生效？

**回答**: 检查AI响应：
- 是否立即开始编程？
- 是否写了冗长的分析报告？
- 代码是否完整可用？
- 是否遵循企业级标准？
