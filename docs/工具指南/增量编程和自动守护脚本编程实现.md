### 1.3 核心代码解析

#### 1.3.1 行数统计核心算法

**方法1：Git Diff统计（推荐）**

```bash
# 核心原理：统计暂存区和工作区的新增行数
count_git_new_lines() {
    # 统计暂存区新增行数（已git add的文件）
    local staged_lines=$(git diff --cached --numstat 2>/dev/null | awk '{sum+=$1} END {print sum+0}')
    
    # 统计工作区新增行数（未git add的文件）
    local unstaged_lines=$(git diff --numstat 2>/dev/null | awk '{sum+=$1} END {print sum+0}')
    
    # 总计
    local total=$((staged_lines + unstaged_lines))
    echo "$total"
}
```

**工作原理**:
1. `git diff --cached --numstat`: 显示暂存区文件的统计信息
2. `awk '{sum+=$1} END {print sum+0}'`: 累加第1列（新增行数）
3. `git diff --numstat`: 显示工作区文件的统计信息
4. 两者相加得到总新增行数

**示例输出**:
```bash
$ git diff --numstat
45      3       src/checkers/new-checker.ts
12      0       src/types/index.ts
# 解释: 45行新增, 3行删除, 文件路径
```

#### 1.3.3 检查点触发逻辑

**智能触发算法**:
```bash
# 监控循环（每10秒检查一次）
while true; do
    # 读取当前状态
    local state=$(read_state)
    local current_count=$(echo "$state" | grep -o '"currentLineCount": [0-9]*' | awk '{print $2}')
    local last_checkpoint=$(echo "$state" | grep -o '"lastCheckpoint": [0-9]*' | awk '{print $2}')
    
    # 统计当前新增行数
    local new_lines=$(count_git_new_lines)
    
    # 更新计数器
    if [ "$new_lines" -gt 0 ] && [ "$new_lines" != "$current_count" ]; then
        current_count=$new_lines
        log "INFO" "检测到新增代码: $current_count 行"
        
        # 检查点1: 100行
        if [ "$current_count" -ge 100 ] && [ "$last_checkpoint" -lt 100 ]; then
            trigger_100_checkpoint
            update_state "$current_count" "$current_count" 100
            last_checkpoint=100
        fi
        
        # 检查点2: 200行
        if [ "$current_count" -ge 200 ] && [ "$last_checkpoint" -lt 200 ]; then
            trigger_200_checkpoint
            update_state "$current_count" "$current_count" 200
            last_checkpoint=200
        fi
        
        # 检查点3: 280行警告
        if [ "$current_count" -ge 280 ] && [ "$last_checkpoint" -lt 280 ]; then
            trigger_280_warning
            update_state "$current_count" "$current_count" 280
            last_checkpoint=280
        fi
        
        # 检查点4: 300行质量门禁
        if [ "$current_count" -ge 300 ]; then
            trigger_300_quality_gate
            # 质量门禁会自动重置计数器
        fi
    fi
    
    sleep 10  # 每10秒检查一次
done
```

**关键逻辑**:
1. **避免重复触发**: 使用 `last_checkpoint` 记录已触发的检查点
2. **递进式检查**: 必须依次通过100→200→280→300
3. **自动重置**: 300行质量门禁通过后自动重置为0

#### 1.3.4 质量门禁实现

**300行质量门禁核心代码**:

```bash
trigger_300_quality_gate() {
    log "CRITICAL" "🛑 已达到300行代码阈值 - 触发质量门禁！"
    
    local all_passed=true
    
    # ━━━ 第1关：TypeScript类型检查 ━━━
    echo "━━━ 第1关：TypeScript类型检查 ━━━"
    if [ -f "src/SmartAbp.Vue/package.json" ]; then
        if (cd src/SmartAbp.Vue && npm run type-check); then
            log "SUCCESS" "✅ TypeScript检查通过"
            echo "✅ TypeScript: 通过"
        else
            log "ERROR" "❌ TypeScript检查失败"
            echo "❌ TypeScript: 失败"
            all_passed=false
        fi
    fi
    
    # ━━━ 第2关：ESLint代码规范 ━━━
    echo "━━━ 第2关：ESLint代码规范 ━━━"
    if [ -f "src/SmartAbp.Vue/package.json" ]; then
        if (cd src/SmartAbp.Vue && npm run lint -- --max-warnings 0); then
            log "SUCCESS" "✅ ESLint检查通过"
            echo "✅ ESLint: 通过"
        else
            log "ERROR" "❌ ESLint检查失败"
            echo "❌ ESLint: 失败"
            all_passed=false
        fi
    fi
    
    # ━━━ 第3关：架构合规检查 ━━━
    echo "━━━ 第3关：架构合规检查 ━━━"
    local violations=0
    
    if [ -d "src/SmartAbp.Vue/packages" ]; then
        # 检查相对路径违规
        local relative_path_count=$(grep -r "'\.\./" src/SmartAbp.Vue/packages/ 2>/dev/null | grep -v node_modules | wc -l | tr -d ' ')
        
        # 检查主应用引用违规
        local main_app_ref_count=$(grep -r "@/" src/SmartAbp.Vue/packages/ 2>/dev/null | grep -v node_modules | wc -l | tr -d ' ')
        
        violations=$((relative_path_count + main_app_ref_count))
        
        if [ "$violations" -eq 0 ]; then
            log "SUCCESS" "✅ 架构合规检查通过"
            echo "✅ 架构合规: 通过"
        else
            log "ERROR" "❌ 架构合规检查失败: $violations 处违规"
            echo "❌ 架构合规: 失败 ($violations 处违规)"
            all_passed=false
        fi
    fi
    
    # ━━━ 质量门禁结果 ━━━
    if [ "$all_passed" = true ]; then
        log "SUCCESS" "🎉 质量门禁检查全部通过！"
        
        # 提示下一步
        echo "📋 下一步建议："
        echo "   A. 执行Git同步: pwsh scripts/git/git-safe-sync.ps1 -AutoCommit"
        echo "   B. 继续开发（重置计数器）"
        echo "   C. 暂停并生成进度报告"
        
        # 重置计数器
        update_state 0 0 0
        return 0
    else
        log "ERROR" "❌ 质量门禁检查失败！"
        echo "⚠️  请修复上述错误后再继续开发"
        return 1
    fi
}
```

**三关质量检查详解**:

| 关卡 | 检查内容 | 失败影响 | 修复方式 |
|-----|---------|---------|---------|
| 第1关 | TypeScript类型检查 | 阻止继续编程 | 修复类型错误 |
| 第2关 | ESLint代码规范 | 阻止继续编程 | 运行 `npm run lint --fix` |
| 第3关 | 架构合规检查 | 阻止继续编程 | 修复相对路径和@/引用 |

#### 2.3.1 定时器核心逻辑

```bash
monitor_mode() {
    log "INFO" "启动规则加载提醒监控模式..."
    log "INFO" "提醒间隔: $REMINDER_INTERVAL 秒 (30分钟)"
    
    init_state
    
    local state=$(read_state)
    local count=$(echo "$state" | grep -o '"reminderCount": [0-9]*' | awk '{print $2}')
    
    # 立即显示一次提醒
    ((count++))
    show_reminder "$count"
    update_state "$count"
    
    # 持续监控循环
    while true; do
        # 等待30分钟
        sleep "$REMINDER_INTERVAL"
        
        # 显示提醒
        ((count++))
        show_reminder "$count"
        update_state "$count"
        
        # 发送系统通知
        if command -v osascript &> /dev/null; then
            # macOS通知
            osascript -e "display notification \"AI需要重新加载规则文件\" with title \"AI规则提醒\" sound name \"Glass\"" 2>/dev/null || true
        elif command -v notify-send &> /dev/null; then
            # Linux通知
            notify-send "AI规则提醒" "AI需要重新加载规则文件" 2>/dev/null || true
        fi
    done
}
```

**工作原理**:
1. `sleep $REMINDER_INTERVAL`: 等待1800秒（30分钟）
2. `show_reminder $count`: 显示彩色提醒界面
3. `update_state $count`: 更新状态（提醒次数+1）
4. 发送系统通知（可选）

```bash
check_rule_files() {
    local missing_files=()
    local total_files=${#RULE_FILES[@]}
    local existing_files=0
    
    # 遍历所有规则文件
    for rule_file in "${RULE_FILES[@]}"; do
        if [ -f "$PROJECT_ROOT/$rule_file" ]; then
            ((existing_files++))
        else
            missing_files+=("$rule_file")
        fi
    done
    
    # 显示缺失的文件
    if [ ${#missing_files[@]} -gt 0 ]; then
        print_warning "发现 ${#missing_files[@]} 个规则文件缺失:"
        for file in "${missing_files[@]}"; do
            echo "   ❌ $file"
        done
        echo ""
    fi
    
    echo "   📊 规则文件状态: $existing_files/$total_files 存在"
}
```

## 📊 第4章：技术细节和最佳实践

### 4.1 性能优化

#### Git Diff优化

```bash
# 优化前：扫描所有文件（慢）
find src/ -name "*.ts" | xargs wc -l

# 优化后：只统计变更文件（快）
git diff --numstat | awk '{sum+=$1} END {print sum+0}'
```

**性能对比**:
- **优化前**: 扫描10000个文件，耗时约5秒
- **优化后**: 只扫描变更文件（通常<100个），耗时约0.1秒

#### 状态文件优化

```bash
# 使用JSON格式存储状态
# 优点：
```

### Q1: 监控脚本意外停止怎么办？

**检查方法**:
```bash
# 检查tmux会话是否存在
tmux list-sessions

# 查看日志
tail -f logs/ai-line-counter.log
tail -f logs/ai-rule-reminder.log
```

**解决方案**:
```bash
# 重新启动
./scripts/dev-start.sh
```

### Q2: Git diff统计不准确？

**原因**:
- 可能有未跟踪的新文件（untracked files）

**解决方案**:
```bash
# 先添加所有新文件
git add .

# 然后再统计
./scripts/quality/auto-line-counter.sh check
```

### Q3: 质量门禁一直失败怎么办？

**步骤1**: 查看详细错误
```bash
# 手动运行TypeScript检查
cd src/SmartAbp.Vue && npm run type-check

# 手动运行ESLint检查
cd src/SmartAbp.Vue && npm run lint
```

**步骤2**: 修复错误后重试
```bash
# 重新触发质量门禁
./scripts/quality/auto-line-counter.sh gate
```

### Q4: 如何临时禁用某个检查？

**方法1**: 修改质量门禁代码
```bash
# 编辑脚本
vim scripts/quality/auto-line-counter.sh

# 注释掉某个检查
# 例如，禁用ESLint检查：
# if (cd src/SmartAbp.Vue && npm run lint -- --max-warnings 0); then
#     ...
# fi
```

**方法2**: 使用环境变量
```bash
# 设置跳过标志
export SKIP_ESLINT=true

# 在脚本中检查
if [ "$SKIP_ESLINT" != "true" ]; then
    # 执行ESLint检查
fi
```
