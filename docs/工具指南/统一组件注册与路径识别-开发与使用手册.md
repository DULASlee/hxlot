# SmartAbp 统一组件注册与路径识别 - 开发与使用手册

本手册适用于 SmartAbp 前端（Vue3 + Vite + pnpm workspace）。目标是在保证各 packages 物理隔离、可单独发布的前提下，为“应用层”提供统一、稳定、可维护的组件自动注册与路径识别能力，解决“导出/导入路径混乱、命名不一致、HMR 失效”等问题。

---

## 一、架构与职责

- 应用层统一插件（运行时）
  - 文件：`src/SmartAbp.Vue/src/plugins/lowcode-components.ts`
  - 职责：自动扫描并注册 packages 组件，统一命名前缀；提供 DEV 清理缓存的快捷入口。
- Vite 插件（开发期增强）
  - 文件：`src/SmartAbp.Vue/packages/lowcode-tools/src/vite/index.ts`
  - 职责：监听 Dev WebSocket 事件，清理解析缓存，解决 HMR 场景“路径变更未生效”。

命名前缀约定（避免冲突、可读可控）：
- `Lc` → lowcode-core
- `Ld` → lowcode-designer
- `Ls` → lowcode-shared
- `Lu` → lowcode-ui-vue（预留，存在即纳入）

---

## 二、快速开始（3 步）

1) 在应用入口启用统一插件（已接入）

```ts
// src/SmartAbp.Vue/src/main.ts
import LowCodeComponentsPlugin from './plugins/lowcode-components'

app
  .use(pinia)
  .use(router)
  .use(i18n)
  .use(ElementPlus)
  .use(hljsVuePlugin)
  .use(LowCodeComponentsPlugin) // 统一组件注册入口
```

2) Vite 中启用开发插件（已接入）

```ts
// src/SmartAbp.Vue/vite.config.ts
import vitePluginLowCode from './packages/lowcode-tools/src/vite'

export default defineConfig({
  plugins: [
    // ...其他插件
    vitePluginLowCode(), // 开发期：用于清理组件解析缓存
  ]
})
```

3) 组件命名与目录放置
- 文件名使用 PascalCase：`SmartFormBuilder.vue`
- 目录支持三种模式（解析优先级如下）：
  - `components/${ComponentName}.vue`
  - `components/${ComponentName}/index.vue`
  - `components/${kebab-case}/${ComponentName}.vue`

放置示例（以 lowcode-core 为例）：
```
packages/lowcode-core/src/components/SmartFormBuilder/SmartFormBuilder.vue
```
使用方式（无需手动 import）：
```
<LcSmartFormBuilder ... />
```

## 三、统一插件的行为与扩展

- 自动扫描范围（默认）
  - `packages/lowcode-core/src/components/**/*.vue`
  - `packages/lowcode-designer/src/components/**/*.vue`
  - `packages/lowcode-shared/src/components/**/*.vue`
  - `packages/lowcode-ui-vue/src/components/**/*.vue`（预留，存在即纳入）

- 前缀派生规则（运行时）
```ts
// inside lowcode-components.ts
const prefix = path.includes('/lowcode-core/') ? 'Lc'
            : path.includes('/lowcode-designer/') ? 'Ld'
            : path.includes('/lowcode-shared/') ? 'Ls'
            : path.includes('/lowcode-ui-vue/') ? 'Lu'
            : null
```

- DEV 辅助（可选）
  - 控制台调用清理缓存（由 Vite 插件响应）：
    ```js
    __smartabp_clearComponentCache()
    ```

- 如何扩展扫描包
  - 在 `src/plugins/lowcode-components.ts` 增加一条 glob 路径，并在 `deriveName` 增加对应前缀映射即可。

## 四、命名规范与约束

- 组件名 = 前缀 + 文件名（PascalCase），如 `LcSmartDataTable`
- 单文件组件 `.vue` 默认导出，不需要额外 index.ts
- 禁止项（关键）：
  - 组件名不得与其他包前缀冲突
  - 业务组件不得放入 shared，仅原子复用能力放入 shared
  - packages 内禁止引用主应用 `@/`（黑盒原则）

## 五、常见问题（FAQ）

- Q1：新组件放入后，开发时模板识别不到？
  - A：执行 `__smartabp_clearComponentCache()`，或重启 Dev Server。

- Q2：组件名冲突（不同包均存在 `Toolbar.vue`）？
  - A：依靠前缀 Lc/Ld/Ls/Lu 自动区分；若仍冲突，调整文件名使语义更清晰。

- Q3：生产环境未打包入某个组件？
  - A：确认组件被使用（模板引用或显式 import），并检查目录结构是否匹配三种模式之一。

- Q4：IDE 报类型找不到某聚合包？
  - A：应用层统一入口已替代聚合包；如需聚合类型提示，可在 `tsconfig.json` 添加 paths，或为该包提供 `index.d.ts`。

## 七、纳入新 UI 包（进阶）

1) 为新包确定前缀（如 `Lu`）。
2) 在 `lowcode-components.ts` 中追加扫描路径与前缀映射。
3) 在新包建立 `src/components/**` 目录，组件按 PascalCase 命名。
4) 运行 `__smartabp_clearComponentCache()` 并验证。
