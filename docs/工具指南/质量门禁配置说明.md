# SmartAbp CI/CD 质量门禁配置说明

## 🏗️ 质量门禁体系架构

### 三层质量保证机制

```
开发阶段          提交阶段          CI/CD阶段
    ↓                ↓                ↓
本地质量检查  →  Git Hooks检查  →  GitHub Actions
    ↓                ↓                ↓
实时反馈        提交前拦截       自动化验证
```

## 🔧 Git Hooks 配置

### 1. pre-commit Hook
**位置**: `.git/hooks/pre-commit`
**功能**: 提交前四重强制检查
- 🏗️ 架构整洁检查（0违规）
- 🔄 代码去重检查（0重复）  
- ⚡ 类型检查（0错误）
- 🚀 编译检查（必须成功）

### 2. pre-push Hook
**位置**: `.git/hooks/pre-push`
**功能**: 推送前最终安全检查
- 保护main分支
- 最终架构和重复代码检查

### 3. commit-msg Hook
**位置**: `.git/hooks/commit-msg`
**功能**: 提交消息格式验证
- 基于Conventional Commits规范
- 强制使用标准前缀：feat/fix/docs等

## 🚀 CI/CD Pipeline 配置

### GitHub Actions工作流
**位置**: `.github/workflows/quality-gate.yml`

#### 并行任务执行
1. **architecture-check**: 架构整洁检查
2. **duplicate-check**: 代码去重检查  
3. **frontend-quality**: 前端质量检查（TypeScript + ESLint + Build）
4. **backend-quality**: 后端质量检查（编译 + 测试）
5. **quality-gate-summary**: 质量门禁汇总

#### 检查标准
- **架构违规**: 0个
- **代码重复**: 0个
- **类型错误**: 0个
- **编译错误**: 0个
- **测试失败**: 0个

## 🛠️ 质量检查脚本

### 1. CI质量检查脚本
**位置**: `scripts/ci-quality-check.sh`
**用途**: CI/CD环境执行
**功能**: 完整的四重质量检查

### 2. 本地质量检查脚本
**位置**: `scripts/local-quality-check.sh`
**用途**: 开发者本地执行
**功能**: 模拟CI环境检查

## 📋 使用指南

### 开发者本地验证
```bash
# 提交前手动检查
bash scripts/local-quality-check.sh

# 通过后安全提交
bash scripts/git-safe-sync.sh --non-interactive --auto-commit
```

### CI/CD环境部署
1. **启用GitHub Actions**: 推送代码时自动触发
2. **分支保护规则**: 要求通过所有检查才能合并
3. **状态检查**: PR必须通过quality-gate检查

## 🎯 质量标准

### 企业级95分标准
- **架构整洁**: 100%符合黑盒原则
- **代码质量**: 0个TypeScript错误，0个ESLint警告
- **重复代码**: 0个同名组件/方法/类型
- **构建成功**: 前端和后端100%编译成功
- **测试通过**: 单元测试100%通过

### 失败处理
- **立即反馈**: Git钩子提供即时反馈
- **阻止提交**: 不符合标准的代码无法提交
- **CI拦截**: GitHub Actions确保远程代码质量
- **分支保护**: main分支受到多重保护

这个质量门禁体系确保每一行代码都符合企业级标准！
