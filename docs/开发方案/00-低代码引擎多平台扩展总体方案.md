# 低代码引擎多平台扩展总体方案

**项目**: SmartAbp低代码引擎平台扩展
**版本**: v1.0
**更新日期**: 2025-10-21
**文档状态**: ✅ 已完成

---

## 📋 一、项目概述

### 1.1 项目背景

**现状**：
- DevKit低代码引擎内核仅支持Vue3 + Element Plus Web代码生成
- 后端代码生成器（Domain/Service/Controller/DTO）完善
- 前端代码生成器仅针对Web CRUD场景

**新需求**：
- 支持数字大屏代码生成（MES、智慧工地项目）
- 支持UniApp移动端代码生成（iOS/Android/H5）
- 不同平台的前端代码差异巨大

### 1.2 核心目标

1. ✅ 扩展DevKit核心，支持多平台代码生成能力
2. ✅ 建立PlatformAdapter机制，实现平台模板隔离
3. ✅ 重构前端生成器架构，保持后端100%复用
4. ✅ 保证向后兼容，现有Web生成器零破坏
5. ✅ 实现Dashboard实时数据推送（SignalR）
6. ✅ 实现UniApp离线数据同步

## 🏗️ 二、总体架构设计

### 2.1 混合架构方案（最优方案）

**架构模式**：共享核心（80%） + 前端独立（20%）

```
┌──────────────────────────────────────────────────────┐
│         DevKit.Core（统一核心 - 80%复用）              │
│  ┌────────────────────────────────────────────────┐  │
│  │  CodeGeneratorEngine（编排引擎）                 │  │
│  │  UnifiedMetadataSDK（元数据SDK - 100%复用）     │  │
│  │  ITemplateEngine（模板引擎 - 100%复用）          │  │
│  │  Backend Generators（后端生成器 - 100%复用）     │  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘
                         ↓ 依赖
┌──────────────────────────────────────────────────────┐
│      PlatformAdapter（平台适配层 - 新增核心组件）      │
│  - 平台模板路径管理                                    │
│  - 平台特定代码生成逻辑                               │
│  - 模板选择和渲染                                     │
└──────────────────────────────────────────────────────┘
                         ↓ 调用
┌──────────────────────────────────────────────────────┐
│      Frontend Generators（前端生成器 - 20%独立）      │
│  ┌─────────────┬────────────────┬──────────────────┐ │
│  │ WebGenerator│DashboardGen    │ UniAppGenerator  │ │
│  │ (现有优化)   │ (Phase 2新增)  │ (Phase 3新增)     │ │
│  └─────────────┴────────────────┴──────────────────┘ │
└──────────────────────────────────────────────────────┘
```

### 2.2 代码复用率

| 层次 | 复用率 | 说明 |
|------|-------|------|
| 后端生成器 | 100% | Domain/Service/Controller/DTO完全复用 |
| 核心引擎 | 100% | CodeGeneratorEngine/MetadataSDK/TemplateEngine复用 |
| 平台适配器 | 100% | 新增，但三个平台共享 |
| 前端生成器 | 20% | 不同平台独立模板，共享基类 |
| **总体复用率** | **80%** | 符合混合架构设计目标 |

## 📅 三、开发计划（7周）

### 3.1 总体时间线

```
Week 1: Phase 1 - 低代码引擎核心重构
Week 2: Phase 2A - Dashboard生成器开发
Week 3: Phase 2B - Dashboard前端链路开发
Week 4: Phase 3A - UniApp生成器开发
Week 5: Phase 3B - UniApp前端链路开发
Week 6: Phase 4 - Dashboard后端链路开发
Week 7: Phase 5 - UniApp后端链路开发
```

### 3.2 各阶段详细计划

#### Phase 1：低代码引擎核心重构（1周）

**目标**：扩展DevKit核心，支持多平台

**核心交付**：
- `PlatformTypes.cs`（平台枚举）
- `PlatformAdapter.cs`（平台适配器）
- `BaseFrontendGenerator.cs`（前端生成器基类）
- `WebGenerator.cs`（重构现有生成器）
- `CodeGeneratorEngine.cs`（扩展）
- CLI扩展（支持`-p`参数）

**验收标准**：
- ✅ 代码复用率≥80%
- ✅ 向后兼容（现有Web生成器零破坏）
- ✅ 代码质量≥95分

#### Phase 2A：Dashboard生成器开发（1周）

**目标**：实现数字大屏代码生成器

**核心交付**：
- `DashboardGenerator.cs`（继承BaseFrontendGenerator）
- 通用模板（layout、kpi-card、realtime-chart、websocket-client、realtime-store）
- MES行业模板（plc-monitor、production-line、equipment-status）
- 智慧工地行业模板（video-surveillance、tower-crane、elevator、dust-monitoring）

**验收标准**：
- ✅ 生成的大屏代码质量≥95分
- ✅ 模板渲染正常
- ✅ 支持MES和智慧工地两类行业模板

#### Phase 2B：Dashboard前端链路开发（1周）

**目标**：实现数字大屏前端完整链路

**核心交付**：
- `useWebSocket.ts`（WebSocket客户端）
- `productionLineRealtimeStore.ts`（产线实时数据Store）
- `KPICard.vue`（KPI卡片组件）
- `RealtimeChart.vue`（实时图表组件）
- `ProductionLineDashboard.vue`（产线监控大屏）
- `SmartConstructionDashboard.vue`（智慧工地大屏）

**验收标准**：

## 🎯 四、关键技术点

### 4.1 平台差异对比

| 维度 | Vue3+ElementPlus | 数字大屏 | UniApp |
|------|-----------------|---------|--------|
| 组件库 | Element Plus | ECharts + 自定义 | uni-ui |
| HTML标签 | div/span/p | div（大屏布局） | view/text/button |
| API调用 | axios | axios + WebSocket | uni.request |
| 数据流 | HTTP CRUD | WebSocket实时推送 | HTTP CRUD + 离线同步 |
| 布局 | 响应式栅格 | 固定分辨率（1920×1080） | rpx响应式 |
| 差异度 | 基准 | ⭐⭐⭐⭐⭐ 极高 | ⭐⭐⭐⭐⭐ 极高 |

### 4.2 核心技术栈

**前端**：
- Vue3 + TypeScript
- Element Plus（Web）
- ECharts（Dashboard）
- uni-ui（UniApp）
- SignalR客户端（Dashboard）

**后端**：
- ABP vNext（DDD）
- SignalR（实时推送）
- JWT认证
- EF Core（数据访问）
- Redis（缓存 + SignalR BackPlane）

## 🚀 八、执行建议

### 8.1 开发顺序

**严格按照Phase 1→2→3→4→5顺序执行**

**原因**：
- Phase 1是基础架构，后续所有阶段都依赖它
- Phase 2/3是前端生成器，可以独立开发
- Phase 4/5是后端链路，可以在Phase 2/3完成后并行开发

### 8.2 风险控制

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 向后兼容性破坏 | 中 | 高 | 完整的回归测试 |
| 性能下降 | 低 | 中 | 性能基准测试 |
| 需求变更 | 中 | 中 | 敏捷迭代 |
| 人员不足 | 低 | 高 | 提前准备人力储备 |
