## 1.3 基础概念理解

### 🧬 组件DNA (ComponentDNA)

**什么是组件DNA？**

组件DNA是ComponentGenie为每个组件生成的"数字指纹"，包含：

```typescript
interface ComponentDNA {
  /** 结构哈希 - 基于代码结构的唯一ID */
  structuralHash: string        // "abc123def456"
  
  /** 行为模式 - 组件特征向量 [0-1] */
  behaviorPattern: number[]     // [1, 1, 0, 1, 0, 0.3, 1, 1]
  
  /** 性能评分 (0-100) - 越高越好 */
  performanceScore: number      // 85
  
  /** 复杂度评分 (0-100) - 越高越简单 */
  complexityScore: number       // 92
  
  /** 创建时间戳 */
  createdAt: number            // 1641234567890
}
```

**行为模式向量说明**:

```yaml
索引0 - defineProps使用: 1=使用, 0=未使用
索引1 - defineEmits使用: 1=使用, 0=未使用  
索引2 - 响应式数据: 1=使用ref/reactive, 0=未使用
索引3 - 计算属性: 1=使用computed, 0=未使用
索引4 - 监听器: 1=使用watch, 0=未使用
索引5 - 函数数量: 归一化到[0-1]
索引6 - 模板使用: 1=有<template>, 0=无模板
索引7 - 导入使用: 1=有import, 0=无导入
```

### 🏷️ 组件分类 (ComponentCategory)

**7种智能分类**:

```typescript
type ComponentCategory =
  | 'FORM_COMPONENT'        // 表单组件 - 包含表单元素和验证
  | 'DATA_DISPLAY'          // 数据展示 - 表格、列表、图表等
  | 'LAYOUT_COMPONENT'      // 布局组件 - 容器、网格、导航等
  | 'INTERACTIVE_COMPONENT' // 交互组件 - 按钮、菜单、弹窗等
  | 'UTILITY_COMPONENT'     // 工具组件 - 纯逻辑、无UI
  | 'BUSINESS_COMPONENT'    // 业务组件 - 复杂业务逻辑
  | 'UNKNOWN'               // 未知类型 - 无法分类
```

**分类准确率**:

| 组件类型 | 准确率 | 典型特征 |
|---------|-------|----------|
| FORM_COMPONENT | 94% | 包含form、input、validation |
| DATA_DISPLAY | 91% | 包含table、list、数据渲染 |
| LAYOUT_COMPONENT | 88% | 包含container、grid、flex |
| INTERACTIVE_COMPONENT | 85% | 包含事件处理、用户交互 |
| UTILITY_COMPONENT | 92% | 纯逻辑、无template |
| BUSINESS_COMPONENT | 78% | 复杂业务逻辑、多功能 |

### 💡 优化建议 (OptimizationSuggestion)

**AI会自动生成4类优化建议**:

```typescript
interface OptimizationSuggestion {
  /** 建议类型 */
  type: 'performance' | 'structure' | 'reusability' | 'maintainability'
  
  /** 建议描述 */
  message: string
  
  /** 影响程度 (1-5) - 数值越高影响越大 */
  impact: number
  
  /** 实施难度 (1-5) - 数值越高实施越困难 */  
  difficulty: number
}
```

**建议类型详解**:

```yaml
performance (性能优化):
  示例: "组件代码较复杂，建议拆分为更小的子组件"
  触发: performanceScore < 60
  
structure (结构优化):  
  示例: "圈复杂度较高，建议简化条件逻辑"
  触发: complexityScore < 50
  
reusability (复用性优化):
  示例: "建议添加Props接口提高组件复用性"  
  触发: 业务组件但无props定义
  
maintainability (维护性优化):
  示例: "建议添加JSDoc注释提高代码可读性"
  触发: 公共方法无文档注释
```

## 2.3 Vue3组合式API使用

### 🎛️ useComponentAI Composable

**创建Vue组合式API函数**:

```typescript
// src/composables/useComponentAI.ts
import { ref, computed } from 'vue'
import { analyzeComponent, type ComponentAnalysis } from '@smartabp/lowcode-shared'

export function useComponentAI() {
  const analysis = ref<ComponentAnalysis | null>(null)
  const isAnalyzing = ref(false)
  const error = ref<string | null>(null)

  // 🧠 分析组件代码
  const analyzeCode = async (name: string, code: string) => {
    isAnalyzing.value = true
    error.value = null
    
    try {
      analysis.value = analyzeComponent(name, code)
      console.log(`🤖 AI分析完成: ${name}`)
    } catch (err) {
      error.value = err instanceof Error ? err.message : '分析失败'
      console.error('AI分析错误:', err)
    } finally {
      isAnalyzing.value = false
    }
  }

  // 📊 计算属性
  const suggestions = computed(() => analysis.value?.suggestions || [])
  const confidence = computed(() => analysis.value?.confidence || 0)
  const category = computed(() => analysis.value?.category || 'UNKNOWN')
  const performanceScore = computed(() => analysis.value?.dna.performanceScore || 0)
  
  // 🎯 优化建议分类
  const performanceSuggestions = computed(() => 
    suggestions.value.filter(s => s.type === 'performance')
  )
  
  const structureSuggestions = computed(() =>
    suggestions.value.filter(s => s.type === 'structure')  
  )

  return {
    // 状态
    analysis,
    isAnalyzing,
    error,
    
    // 方法
    analyzeCode,
    
    // 计算属性  
    suggestions,
    confidence,
    category,
    performanceScore,
    performanceSuggestions,
    structureSuggestions
  }
}
```

### 🎨 在Vue组件中使用

```vue

    <div v-if="analysis" class="analysis-results">

        <el-empty v-if="suggestions.length === 0" description="暂无优化建议" />
        
        <div v-else class="suggestions-list">

              </template>
            </el-alert>
          </div>
        </div>
      </el-card>
    </div>

    <!-- 错误提示 -->

  </div>

<script setup lang="ts">
import { ref } from 'vue'
import { useComponentAI } from '@/composables/useComponentAI'

const {
  analysis,
  isAnalyzing,
  error,
  analyzeCode,

  confidence,
  category,
  performanceScore

// 当前编辑的代码

<template>
  <div class="sample-component">
    <h1>{{ title }}</h1>
    <p>{{ description }}</p>
  </div>
</template>

<script setup lang="ts">
defineProps<{
  title: string
  description: string
}>()
</script>
`)

// 🧠 分析当前代码
const analyzeCurrentCode = () => {
  analyzeCode('SampleComponent', currentCode.value)
}

// 🎨 UI辅助方法
const getConfidenceType = (conf: number) => {
  if (conf >= 0.8) return 'success'
  if (conf >= 0.6) return 'warning' 
  return 'danger'
}

const getScoreColor = (score: number) => {
  if (score >= 80) return '#67c23a'
  if (score >= 60) return '#e6a23c'
  return '#f56c6c'
}

const getSuggestionType = (type: string) => {
  const typeMap = {
    'performance': 'error',
    'structure': 'warning', 
    'reusability': 'info',
    'maintainability': 'success'
  }
  return typeMap[type] || 'info'
}
</script>
```
