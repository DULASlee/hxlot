## 🏗️ 技术架构

### 整体架构

```
DevKit v2.0架构
├─ CLI层（devkit命令）
│  ├─ InitCommandHandler       # devkit init
│  ├─ GenerateCommandHandler   # devkit generate
│  ├─ QualityCommandHandler    # devkit quality
│  └─ PartialCommandHandler    # devkit partial
│
├─ 核心层（Core）
│  ├─ ConfigLoader              # 配置加载
│  ├─ ConfigValidator           # 配置验证
│  ├─ LowCodeDirectoryManager   # 目录管理
│  ├─ GeneratorOrchestrator     # Generator编排
│  ├─ IncrementalHashCache      # 增量缓存
│  └─ QualityGateExecutor       # 质量门禁
│
├─ Generator层
│  ├─ DomainGenerator           # Domain层生成
│  ├─ ApplicationGenerator      # Application层生成
│  └─ VueCrudPageGenerator      # Frontend层生成
│
└─ 模板层
   ├─ TemplateManager           # 模板管理
   └─ Handlebars.Net            # 模板引擎
```

### 数据流

```
配置文件 (.lowcode/config.json)
    ↓
ConfigLoader（加载+验证）
    ↓
GeneratorOrchestrator（编排）
    ↓
并行执行Generator
├─ DomainGenerator → Domain层代码
├─ ApplicationGenerator → Application层代码
└─ VueCrudPageGenerator → Frontend层代码
    ↓
IncrementalHashCache（增量过滤）
    ↓
批量写入文件
    ↓
QualityGateExecutor（质量检查）
    ↓
生成完成
```

## 🎯 最佳实践建议

### 1. 配置管理

**推荐做法**:
- ✅ 使用版本控制管理 `.lowcode/config.json`
- ✅ 不要提交 `.lowcode/hashes.json`
- ✅ 备份 `.lowcode/backups/`（可选）

### 2. 增量生成

**推荐做法**:
- ✅ 首次生成后，保留 `hashes.json`
- ✅ 只修改需要变更的配置
- ✅ 定期清理缓存（如需完整重新生成）

### 3. 代码保护

**推荐做法**:
- ✅ 用户自定义代码放在 `*.User.cs` 文件中
- ✅ 不要修改生成的 `*.cs` 文件（会被覆盖）
- ✅ 使用Partial类扩展生成的代码

### 4. 质量保证

**推荐做法**:
- ✅ 每次生成后执行 `devkit quality check`
- ✅ 修复所有质量门禁错误
- ✅ 维护技术债务评分≥85分
