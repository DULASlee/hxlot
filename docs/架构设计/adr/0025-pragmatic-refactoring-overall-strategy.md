# ADR-0025: 务实重构总体方案 - 基于代码事实的渐进式架构优化

- **状态**: 已接受
- **日期**: 2025-09-29
- **决策者**: 首席架构师

## 背景

SmartAbp企业级低代码引擎项目面临三大核心矛盾，严重影响开发效率和产品质量：

### 核心问题诊断
1. **文件风暴问题**（严重性：极高）
   - 项目文件总数高达 **20,151个TS文件**
   - 代码生成器为每个微小单元都生成独立文件，直接输出到`src/`目录
   - 造成**毁灭性的I/O压力**，IDE的TypeScript Language Server需要监控、解析数万个文件
   - **这是导致IDE卡顿、内存溢出的罪魁祸首**

2. **内存泄露根源**（严重性：高）
   - **模式一**：组件生命周期与全局事件监听器脱钩，导致永久持有对组件实例的引用
   - **模式二**：Pinia Store中存储了循环引用的组件/DOM实例，导致整个组件树无法被垃圾回收
   - **这是导致大规模内存泄露的直接原因**

3. **架构耦合严重**（严重性：高）
   - `packages`间存在严重的`'../'`和`@/`非法跨层引用，破坏了"黑盒原则"
   - 使得`packages`无法独立构建、测试和版本管理
   - **这是导致架构腐化、可维护性急剧下降的核心原因**

### 技术债务评估
基于影响程度、紧急程度和解决复杂度的量化评估：
- 微前端架构：**拒绝**（过度设计，无法解决核心痛点）
- 按需/增量生成策略：**采纳**（根治问题的战略方向）
- 内存分页/懒加载：**采纳**（直接解决运行时内存问题）

## 决策

采纳**终极务实重构方案**，严格遵循**风险控制优先**和**渐进式重构**哲学。

### 核心原则
1. **基于代码事实**：所有决策基于实际代码分析，避免过度设计
2. **风险可控**：每一步都旨在解决一个已验证的、具体的痛点
3. **渐进式重构**：分阶段实施，确保每个阶段都有明确收益
4. **聚焦核心矛盾**：直接解决三大核心问题

### 四阶段强制执行路径

#### 第一阶段：紧急止血（1周）
**目标**：将IDE内存占用降低70%，热更新时间缩短到3秒内
- 创建代码生成隔离区（`.generated`文件夹）
- 建立IDE性能保护铁律（`.vscode/settings.json`配置）
- 修复高危内存泄露（`useSafeEventListener`组合式函数）

#### 第二阶段：架构边界清晰化（2周）
**目标**：消除所有跨`packages`的非法引用，实现`packages`可独立构建
- 实施TypeScript项目引用（Project References）
- 创建共享基础库`lowcode-shared`
- 修复所有架构违规引用

#### 第三阶段：运行时性能革命（2-3周）
**目标**：实现复杂页面的秒级加载，将运行时内存峰值降低50%
- 实施组件懒加载与内存分页管理
- 采纳`ComponentLazyLoader`和`MemoryManager`（LRU淘汰策略）
- 重构组件注册机制为动态`import()`

#### 第四阶段：战略演进（长期）
**目标**：实现代码生成器的增量生成，从根本上减少生成文件的数量和频率
- 重构代码生成器为增量模式
- 引入基于内容哈希的缓存机制
- 实现`IncrementalCodeGenerator`

## 后果

### 正面影响
1. **精准打击核心矛盾**
   - 文件风暴 → 隔离生成物（Phase 1）
   - 编译缓慢 → TS项目引用（Phase 2）
   - 运行时内存泄露 → 组件懒加载（Phase 3）

2. **风险可控的渐进改进**
   - 每一步都小而具体，易于验证和回滚
   - 第一阶段完成后，开发体验将得到立竿见影的改善
   - 为未来长期、可持续的开发奠定坚实基础

3. **量化收益预期**
   - IDE内存占用降低70%
   - 热更新时间从10秒+缩短到3秒内
   - 编译时间从分钟级降低到秒级
   - 运行时内存峰值降低50%

### 负面影响
1. **短期投入成本**
   - 需要集中资源投入约1-2个月进行重构
   - 需要团队学习新的架构模式和工具

2. **技术要求提升**
   - 对团队成员理解TypeScript项目引用、内存管理等有一定要求
   - 需要建立新的开发规范和流程

## 实施保障

### 质量门禁机制
1. **每日质量检查**：架构整洁检查 + 代码去重检查 + 编译质量检查
2. **阶段验收标准**：每个阶段都有明确的、可量化的验收标准
3. **风险缓解措施**：完整的回滚机制和应急预案

### 知识传承机制
1. **ADR决策记录**：所有关键决策都记录在ADR中
2. **技术文档更新**：同步更新相关技术文档
3. **团队培训计划**：确保团队理解新架构和工具
