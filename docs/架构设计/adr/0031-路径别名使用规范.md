# ADR-0031: 路径别名使用规范

**状态**: 已接受
**日期**: 2025-01-13
**决策者**: 架构团队
**优先级**: P0（阻断性规则）

---

## 背景

SmartAbp 项目使用 pnpm workspace 管理 monorepo，包含多个独立的 packages。为了实现架构三大铁律中的"架构层级依赖"规则，项目使用 `@smartabp/*` 别名来引用 packages，但在实际开发中发现了路径使用不一致的问题。

### 问题案例

```typescript
// ❌ 错误写法1：重复了 src/
import { xxx } from '@smartabp/lowcode-core/src/components/...'

// ❌ 错误写法2：使用相对路径
import { xxx } from '../../packages/lowcode-core/src/components/...'

// ✅ 正确写法
import { xxx } from '@smartabp/lowcode-core/components/...'
```

---

## 决策

### 核心原则

**所有 `@smartabp/*` 别名的配置都已包含 `src/` 目录，因此使用时不需要再写 `/src/`。**

---

## 别名配置规范

### 1. TypeScript 配置（`tsconfig.json`）

```json
{
  "compilerOptions": {
    "paths": {
      "@smartabp/lowcode-core": ["packages/lowcode-core/src/index.ts"],
      "@smartabp/lowcode-core/*": ["packages/lowcode-core/src/*"],
      //                                                    ↑ 已包含 src/

      "@smartabp/lowcode-shared": ["packages/lowcode-shared/src/index.ts"],
      "@smartabp/lowcode-shared/*": ["packages/lowcode-shared/src/*"],

      "@smartabp/lowcode-designer": ["packages/lowcode-designer/index.ts"],
      "@smartabp/lowcode-designer/*": ["packages/lowcode-designer/*"],

      "@smartabp/lowcode-api": ["packages/lowcode-api/src/index.ts"],
      "@smartabp/lowcode-api/*": ["packages/lowcode-api/src/*"],

      "@smartabp/lowcode-tools": ["packages/lowcode-tools/src/index.ts"],
      "@smartabp/lowcode-tools/*": ["packages/lowcode-tools/src/*"],

      "@smartabp/metadata-core": ["packages/metadata-core/src/index.ts"],
      "@smartabp/metadata-core/*": ["packages/metadata-core/src/*"]
    }
  }
}
```

**配置说明**：
- `@smartabp/lowcode-core/*` → `packages/lowcode-core/src/*`
- 别名路径已包含 `src/` 目录
- 因此使用时直接写 `@smartabp/lowcode-core/components/...`

### 2. Vite 配置（`vite.config.ts`）

```typescript
export default defineConfig({
  resolve: {
    alias: {
      "@smartabp/metadata-core": fileURLToPath(
        new URL("./packages/metadata-core/src", import.meta.url),
      ),
      //                                      ↑ 直接指向 src 目录

      "@smartabp/lowcode-shared": fileURLToPath(
        new URL("./packages/lowcode-shared/src", import.meta.url),
      ),

      "@smartabp/lowcode-core": fileURLToPath(
        new URL("./packages/lowcode-core/src", import.meta.url),
      ),

      "@smartabp/lowcode-designer": fileURLToPath(
        new URL("./packages/lowcode-designer", import.meta.url),
      ),

      "@smartabp/lowcode-api": fileURLToPath(
        new URL("./packages/lowcode-api/src", import.meta.url),
      ),

      "@smartabp/lowcode-tools": fileURLToPath(
        new URL("./packages/lowcode-tools/src", import.meta.url),
      ),
    },
  },
})
```

**配置说明**：
- Vite alias 直接指向 `packages/xxx/src` 目录
- 与 TypeScript 配置保持一致

## 使用规范

### ✅ 正确写法

#### 1. 导入组件

```typescript
// 导入 lowcode-core 的组件
import { SmartFormDesigner } from '@smartabp/lowcode-core/components/SmartFormBuilder/SmartFormDesigner.vue'

// 导入 lowcode-shared 的工具
import { formatDate } from '@smartabp/lowcode-shared/utils/date'

// 导入 metadata-core 的类型
import type { EntityMetadata } from '@smartabp/metadata-core/types'
```

#### 2. 动态导入

```typescript
// 路由懒加载
component: () => import('@smartabp/lowcode-core/components/SmartFormBuilder/SmartFormDesigner.vue')

// 按需加载
const module = await import('@smartabp/lowcode-designer/components/DesignerCanvas.vue')
```

#### 3. 导入主入口

```typescript
// 导入包的主入口
import { LowCodeCore } from '@smartabp/lowcode-core'
import { MetadataCore } from '@smartabp/metadata-core'
```

### ❌ 错误写法

#### 1. 重复 src/ 目录

```typescript
// ❌ 错误：多了 /src/
import { xxx } from '@smartabp/lowcode-core/src/components/...'

// 解析结果：packages/lowcode-core/src/src/components/...
//                                  ^^^^^^^^ 重复了！
```

#### 2. 使用相对路径

```typescript
// ❌ 错误：使用相对路径引用 packages
import { xxx } from '../../packages/lowcode-core/src/components/...'

// 应改为：
import { xxx } from '@smartabp/lowcode-core/components/...'
```

#### 3. 混用主应用别名

```typescript
// ❌ 错误：在 packages 中使用主应用别名 @/
import { xxx } from '@/components/...'

// packages 必须使用 @smartabp/* 别名
```

## 别名路径映射表

| 别名 | 实际路径 | 使用示例 |
|------|---------|---------|
| `@smartabp/lowcode-core/*` | `packages/lowcode-core/src/*` | `@smartabp/lowcode-core/components/...` |
| `@smartabp/lowcode-shared/*` | `packages/lowcode-shared/src/*` | `@smartabp/lowcode-shared/utils/...` |
| `@smartabp/lowcode-designer/*` | `packages/lowcode-designer/*` | `@smartabp/lowcode-designer/views/...` |
| `@smartabp/lowcode-api/*` | `packages/lowcode-api/src/*` | `@smartabp/lowcode-api/services/...` |
| `@smartabp/lowcode-tools/*` | `packages/lowcode-tools/src/*` | `@smartabp/lowcode-tools/helpers/...` |
| `@smartabp/metadata-core/*` | `packages/metadata-core/src/*` | `@smartabp/metadata-core/types/...` |

**关键点**：
- ✅ 别名后直接跟目录名：`components/`、`utils/`、`types/` 等
- ❌ 不要再加 `src/`

## 自动化检测

### ESLint 规则

在 `.eslintrc.cjs` 中添加：

```javascript
module.exports = {
  rules: {
    'no-restricted-imports': [
      'error',
      {
        patterns: [
          {
            group: ['@smartabp/*/src/*'],
            message: '❌ 错误：@smartabp别名已包含src/，不要再写 /src/。正确写法：@smartabp/lowcode-core/components/...'
          },
          {
            group: ['**/packages/**'],
            message: '❌ 错误：禁止使用相对路径引用packages。请使用 @smartabp/* 别名。'
          }
        ]
      }
    ]
  }
}
```

### Git Hooks

在 `.husky/pre-commit` 中添加检查：

```bash
# 检查是否有错误的别名使用
if git diff --cached --name-only | grep -E '\.(ts|vue|js)$' | xargs grep -l '@smartabp/[^/]*/src/' 2>/dev/null; then
  echo "❌ 错误：发现错误的别名路径（包含 /src/）"
  echo "请使用：@smartabp/lowcode-core/components/..."
  echo "而非：@smartabp/lowcode-core/src/components/..."
  exit 1
fi
```

## 迁移指南

### 批量修复命令

```bash
# 查找所有错误路径
cd src/SmartAbp.Vue
grep -r "@smartabp/[^/]*/src/" src/ --include="*.ts" --include="*.vue" --include="*.js"

# 使用 sed 批量替换（macOS/Linux）
find src/ -type f \( -name "*.ts" -o -name "*.vue" -o -name "*.js" \) -exec sed -i '' 's|@smartabp/\([^/]*\)/src/|@smartabp/\1/|g' {} +

# 使用 sed 批量替换（Windows Git Bash）

```

## 附录：常见问题

### Q1: 为什么别名要包含 src/ 目录？

**A**: 这是为了保持 packages 的标准目录结构：
```
packages/lowcode-core/
  ├── src/          ← 源代码目录
  │   ├── index.ts  ← 主入口
  │   ├── components/
  │   ├── utils/
  │   └── types/
  ├── dist/         ← 构建产物
  └── package.json
```

别名指向 `src/` 是为了直接访问源代码，而不是构建产物。

### Q2: lowcode-designer 为什么不包含 src/?

**A**: `lowcode-designer` 是特殊的，它的目录结构是：
```
packages/lowcode-designer/
  ├── index.ts      ← 直接在根目录
  ├── views/
  ├── components/
  └── package.json
```

因此别名配置为：
```json
"@smartabp/lowcode-designer/*": ["packages/lowcode-designer/*"]
```

### Q3: 如何快速判断路径是否正确？

**A**: 记住一个规则：
```typescript
// 别名后面直接跟功能目录，不要加 src/
@smartabp/xxx/ + components/  ✅
@smartabp/xxx/ + utils/       ✅
@smartabp/xxx/ + types/       ✅
@smartabp/xxx/ + src/         ❌ 错误！
```
