# ADR-0038: 后端SSOT驱动的契约类型系统（Phase 3C核心架构）

## 📋 元数据

**状态**: ✅ 已接受并实施完成
**决策日期**: 2025-10-24
**实施日期**: 2025-09 ~ 2025-10
**决策者**: 首席架构师 + 前后端团队
**影响范围**: 类型系统架构、前后端数据一致性、packages独立性
**架构评分**: 95/100（31级AlphaGO最优解）

## 🎯 背景

### 问题现状（Phase 3B遗留问题）

在Phase 3B阶段，SmartAbp项目存在以下类型系统问题：

```yaml
问题1: 类型定义分散
  症状:
    - 主应用定义底层类型（src/types/lowcode-contracts.ts）
    - packages引用主应用类型（破坏黑盒独立性）
    - metadata-core包含重复定义

  影响:
    ❌ packages无法独立使用
    ❌ 类型定义不一致
    ❌ 维护成本高

问题2: 前后端类型不一致
  症状:
    - 手动维护前端类型
    - 后端DTO修改后前端不同步
    - 类型差异导致运行时错误

  影响:
    ❌ BUG率高（类型不匹配）
    ❌ 开发效率低（手动同步）
    ❌ 运行时错误多

问题3: packages依赖混乱
  症状:
    - packages引用@/api/generated（主应用生成API）
    - packages引用src/（主应用目录）
    - 相对路径跨包引用（'../'）

  影响:
    ❌ 破坏黑盒独立性
    ❌ 循环依赖风险
    ❌ 无法单独发布packages

问题4: metadata-core定位模糊
  症状:
    - 既有元数据Schema又有业务类型
    - 与后端DTO重复
    - 与NSwag生成类型重复

  影响:
    ❌ 职责不清
    ❌ 代码重复
    ❌ 维护困难
```

### 业务需求

```yaml
架构要求:
  ✅ packages必须完全黑盒独立（零src/依赖）
  ✅ 前后端类型必须100%一致
  ✅ 类型定义必须有唯一真实来源（SSOT）
  ✅ 主应用和packages类型来源清晰分离

质量要求:
  ✅ TypeScript编译0错误
  ✅ 禁止any类型
  ✅ 架构合规100%
  ✅ 依赖关系清晰

性能要求:
  ✅ 类型生成自动化
  ✅ 类型同步实时
  ✅ 编译速度优化
```

```yaml

铁律2: packages黑盒独立
  ✅ packages只使用契约类型（backend-contracts.ts）
  ❌ 禁止引用@/api/generated（主应用生成API）
  ❌ 禁止引用src/（主应用目录）
  ❌ 禁止相对路径跨包引用（'../'）

铁律3: 主应用使用生成类型
  ✅ 主应用使用NSwag生成的类型
  ❌ 禁止主应用定义契约类型
  ❌ 禁止主应用引用backend-contracts.ts

铁律4: metadata-core废弃
  ❌ 禁止引用@smartabp/metadata-core
  ✅ 使用backend-contracts.ts替代
  ✅ metadata-core仅保留Schema验证功能
```

### 依赖层级规则

```yaml
三层架构（100/100黑盒独立）:

  Layer 0: lowcode-shared（契约类型层）
    - backend-contracts.ts（45个契约类型）
    - 零包依赖，完全独立
    - 职责：提供packages通用类型

  Layer 1: lowcode-core, lowcode-api, lowcode-tools（核心逻辑层）
    - 只能依赖lowcode-shared
    - 使用契约类型进行类型声明
    - 职责：实现业务逻辑

  Layer 2: lowcode-designer（设计器UI层）
    - 依赖shared + core
    - 使用契约类型构建UI
    - 职责：可视化设计器

允许的依赖:
  ✅ Layer 2 → Layer 1 → Layer 0（向下依赖）
  ✅ 同层级单向依赖（如：api→core）

禁止的依赖:
  ❌ Layer 0 → 任何（底层依赖上层）
  ❌ Layer 1 → Layer 2（逆向依赖）
  ❌ 循环依赖（A→B→A）
  ❌ packages → src/api/generated（破坏黑盒）
```

### SSOT流程详解

```yaml
阶段1: 后端定义（SSOT层）

  步骤1: 定义实体
    # src/SmartAbp.Domain/Entities/LowCode/EntityDefinition.cs
    [GenerateSwaggerSchema]
    public class EntityDefinition : FullAuditedAggregateRoot<Guid>
    {
        public string Name { get; set; }
        public string DisplayName { get; set; }
        public List<EntityField> Fields { get; set; }
    }

  步骤2: 定义DTO
    # src/SmartAbp.Application.Contracts/LowCode/EntityDefinitionDto.cs
    public class EntityDefinitionDto
    {
        public Guid Id { get; set; }
        public string Name { get; set; }
        public string DisplayName { get; set; }
        public List<EntityFieldDto> Fields { get; set; }
    }

阶段2: Swagger生成

  后端启动 → Swagger JSON自动生成:
    {
      "EntityDefinitionDto": {
        "type": "object",
        "properties": {
          "id": { "type": "string", "format": "uuid" },
          "name": { "type": "string" },
          "displayName": { "type": "string" },
          "fields": {
            "type": "array",
            "items": { "$ref": "#/components/schemas/EntityFieldDto" }
          }
        }
      }
    }

阶段3: 前端类型生成

  NSwag读取Swagger JSON → 生成TypeScript类型:
    # generated/models/EntityDefinitionDto.ts
    export interface EntityDefinitionDto {
      id: string
      name: string
      displayName: string
      fields: EntityFieldDto[]
    }

阶段4: 契约层同步

  # packages/lowcode-shared/src/types/backend-contracts.ts
  export interface EntityDefinitionDto {
    id: string
    name: string
    displayName: string
    fields: EntityFieldDto[]
  }

  同步方式:
    - 方式1: 手动复制（简单可控）
    - 方式2: 脚本自动同步（高级）
    - 方式3: 共享类型定义文件（推荐）

阶段5: 使用类型

  # packages中使用契约类型
  import type { EntityDefinitionDto } from '@smartabp/lowcode-shared'

  # 主应用使用生成类型
  import type { EntityDefinitionDto } from '@/api/generated/models'
```
