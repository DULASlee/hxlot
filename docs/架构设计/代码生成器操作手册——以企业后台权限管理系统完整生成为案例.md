## 🚀 **第一部分：环境准备和工具启动**

### **步骤1：启动SmartAbp开发环境**

#### 1.1 打开终端，启动后端服务
```bash
# 进入项目根目录
cd /path/to/SmartAbp

# 启动后端API服务
dotnet run --project src/SmartAbp.Web/SmartAbp.Web.csproj

# 验证后端启动成功
# 浏览器访问：http://localhost:44350/swagger
# 确认看到Swagger API文档界面
```

#### 1.2 启动前端开发服务
```bash
# 进入前端目录
cd src/SmartAbp.Vue

# 安装依赖（首次运行）
npm install

# 启动前端开发服务
npm run dev

# 验证前端启动成功
# 浏览器访问：http://localhost:5173
# 确认看到SmartAbp主界面
```

#### 1.3 进入低代码生成器
```bash
# 浏览器访问低代码生成器
http://localhost:5173/lowcode/ultra-simple-studio

# 确认看到"生成企业管理系统"界面
```

### **模块1：组织管理模块生成**

#### **步骤1：数据库表选择**

**操作**：在"选择数据库表"下拉框中选择或创建组织表
```
选择项：AbpOrganizationUnits
描述：组织架构管理表（公司-部门-岗位三级结构）
```

如果表不存在，点击"创建新表"：

**表结构配置**：
```sql
表名：AbpOrganizationUnits
描述：组织架构管理表

字段配置：
├─ Id (Guid) - 主键，自动生成
├─ Name (string, 50) - 组织名称 *必填
├─ Code (string, 20) - 组织编码 *必填 *唯一
├─ DisplayName (string, 100) - 显示名称
├─ Description (string, 500) - 组织描述
├─ ParentId (Guid?) - 父组织ID，外键关联自身
├─ HierarchyPath (string, 200) - 层次路径 *必填
├─ Level (int) - 组织层级，默认值：0
├─ Sort (int) - 排序，默认值：0
├─ Type (int) - 组织类型，枚举：1-集团,2-公司,3-分公司,4-部门
├─ Status (int) - 状态，枚举：1-正常,2-停用,3-冻结
├─ IsLeaf (bool) - 是否叶子节点，默认值：false
├─ TenantId (Guid?) - 租户ID，多租户支持
└─ 标准审计字段：CreationTime, CreatorId, LastModificationTime, LastModifierId, IsDeleted, DeleterId, DeletionTime
```

#### **步骤2：系统基础信息配置**

**配置项填写**：
```yaml

模块名称 (Name): "OrganizationManagement" 
显示名称 (DisplayName): "组织管理"
模块描述 (Description): "企业组织架构管理，支持公司-部门-岗位三级结构"

命名空间 (Namespace): "SmartAbp.OrganizationManagement" # 自动推导
```

**架构配置**：

```yaml
启用多租户 (EnableMultiTenancy): true

启用审计 (EnableAuditing): true
```


## 🎯 **第三部分：高级配置和定制**

### **高级配置1：数据权限配置**

#### **组织数据权限设置**

**配置路径**：高级配置 → 数据权限 → 组织权限

```yaml
数据权限规则：
  全部数据 (DataScope.All):
    - 描述：可访问所有组织的数据
    - 适用角色：系统管理员、超级管理员
    - 风险等级：高
    
  本组织数据 (DataScope.Organization):
    - 描述：只能访问本组织的数据
    - 适用角色：组织管理员、部门经理
    - 包含下级：可配置是否包含下级组织

    - 描述：只能访问自己创建的数据
    - 适用角色：普通员工、实习生
    - 安全等级：最高

自定义数据权限：
  规则表达式：支持基于字段的复杂条件
  示例：OrganizationId IN (SELECT Id FROM UserOrganizations WHERE UserId = @CurrentUserId)
```

## 🎯 **第七部分：常见问题和解决方案**

### **问题1：生成失败**

**症状**：点击"开始生成"后出现错误

**可能原因和解决方案**：
```yaml
数据库连接问题：
  原因：数据库连接字符串配置错误
  解决：检查appsettings.json中的ConnectionStrings配置

表名冲突：
  原因：目标表已存在且结构不匹配
  解决：选择"覆盖现有表"或修改表名

权限名称冲突：
  原因：权限名称与现有权限冲突
  解决：修改权限前缀或检查现有权限定义

模板文件缺失：
  原因：模板文件损坏或路径错误
  解决：重新安装模板或检查templates目录
```

### **问题2：前端界面显示异常**

**症状**：前端页面空白或组件加载失败

**解决方案**：
```bash
# 检查前端编译错误
npm run build

# 检查TypeScript类型错误  
npm run type-check

# 检查ESLint错误
npm run lint

# 重新启动前端服务
npm run dev
```

### **问题3：权限控制不生效**

**症状**：用户能访问没有权限的功能

**排查步骤**：
```yaml
1. 检查权限定义：
   - 确认权限已在数据库中定义
   - 检查权限名称拼写是否正确

2. 检查角色分配：
   - 确认用户已分配正确角色
   - 检查角色权限配置是否正确

3. 检查缓存：
   - 清除权限缓存：Redis FLUSHDB
   - 重新登录用户，触发权限重算

4. 检查前端权限指令：
   - 确认v-permission指令正确使用
   - 检查权限Store数据是否正确
```

### **问题4：性能问题**

**症状**：权限检查响应慢或界面卡顿

**优化方案**：
```yaml
权限缓存优化：
  - 启用Redis缓存
  - 配置合理的缓存过期时间
  - 使用本地缓存减少网络开销

数据库优化：
  - 创建必要的索引
  - 优化查询语句
  - 考虑读写分离

前端优化：
  - 启用虚拟滚动（大数据量）
  - 使用懒加载（权限树）
  - 优化组件渲染性能
```

## 🏆 **第九部分：最佳实践和技巧**

### **最佳实践1：命名规范**

```yaml
实体命名：
  - 使用PascalCase：OrganizationUnit, UserProfile
  - 避免缩写：使用Organization而不是Org
  - 语义明确：CreateUserDto而不是UserCreateInput

权限命名：
  - 层次化结构：ModuleName.ActionName
  - 示例：UserManagement.Create, RoleManagement.AssignPermission
  - 避免过长：不超过50字符

数据库命名：
  - 表名使用复数：Users, Roles, Permissions
  - 字段名使用PascalCase：FirstName, LastName
  - 外键命名：EntityNameId，如OrganizationId
```

### **最佳实践2：权限设计**

```yaml
权限粒度：
  - 功能权限：按业务功能划分，如Create、Update、Delete
  - 数据权限：按数据范围划分，如All、Organization、Department、Self
  - 操作权限：按具体操作划分，如Export、Import、Approve

权限继承：
  - 父权限：模块级权限，如UserManagement.Default
  - 子权限：具体操作权限，如UserManagement.Create
  - 继承规则：拥有父权限自动拥有所有子权限

权限组织：
  - 按业务模块分组：UserManagement, RoleManagement
  - 按功能类型分组：System, Business, Report
  - 按风险等级分组：Low, Medium, High, Critical
```

### **最佳实践3：性能优化**

```yaml
缓存策略：
  - 权限缓存：30分钟过期，变更时立即失效
  - 用户缓存：10分钟过期，登录时刷新
  - 组织缓存：1小时过期，结构变更时失效

查询优化：
  - 使用索引：在常用查询字段上创建索引
  - 分页查询：大数据量时必须分页
  - 延迟加载：权限树按需加载子节点

前端优化：
  - 虚拟滚动：用户列表超过1000条时启用
  - 防抖搜索：搜索输入300ms后执行
  - 组件懒加载：非首屏组件按需加载
```
