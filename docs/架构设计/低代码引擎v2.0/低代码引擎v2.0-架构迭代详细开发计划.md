# SmartAbp 低代码引擎 v2.0 — 架构迭代详细开发计划

更新时间：2025-10-16  作者：架构组（v1.1 技术委员会结论微调）

- 目标：在6周内交付“企业级真实可用”的全栈代码生成器，确保契约一致性、生成质量可验证、用户体验可感知、迭代可持续。
- 原则：契约先行（Contract-first）/ 增量生成与合并保护 / 生成前后双层质量门禁（Shift-left）/ 以业务体验为中心。
- 工程化铁律：低代码质量 = 契约一致性 × 生成质量 × 保护策略（乘法关系，任一为0则整体为0）。

---

## 一、阶段与里程碑（4–6周）

- Phase 1（Week 1）：契约闭环与CLI雏形
  - 后端OpenAPI稳定输出；前端NSwag生成TS客户端并替换手写API。
  - 提供 `lowcode-tools` CLI：`generate --dry-run|--apply`、基础日志与回滚记录。

- Phase 2（Week 2）：后端模板化（ABP）+ ts-morph核心起步 + 增量保护
  - Handlebars.Net 模板固化（Entity/DTO/Profile/AppService/Controller/Permission/DbContext）。
  - 引入 ts-morph：优先覆盖 DTO 类型/Store/路由/API Hooks 的 AST 生成（100%类型安全，零字符串拼接）。
  - 启用 partial class/partial method 与 TS 锚点注释，落地生成区/用户区分离策略。

- Phase 3（Week 3）：质量门禁前置（Shift-left）与锚点/Manifest完善
  - 生成后自动流水线前移为“生成即检”：prettier → eslint（0警告）→ vue-tsc（0错误）→ dotnet build（最小输出）。
  - 完善锚点注释规范与 Manifest（生成清单）机制，支持 `diff/rollback` 与三方合并（three-way merge）。
  - 增加“契约一致性校验脚本”：OpenAPI↔TS Client↔调用端类型一致性比对。

- Phase 4（Week 4）：VForm3 集成与设计-生成闭环
  - 嵌入 VForm3 Designer/Renderer，完成与 unified-schema 的双向绑定。
  - 设计器一键预览/差异/应用；页面可打开并可提交表单。

- Phase 5（Week 5）：质量门禁流水线与快测
  - 生成后自动执行：prettier → eslint（0警告）→ vue-tsc（0错误）→ dotnet build（最小输出）。
  - 模板级 snapshot & 编译快测、菜单/权限/路由可用性快验收。

- Phase 6（Week 6，可选）：性能与规模化验证
  - 50实体全量生成 < 30s；单实体迭代 < 2s；回滚/重试稳定。

## 二、详细任务分解（按周）

### Week 1 — 契约闭环与CLI雏形（P0）
- 后端（ABP）
  - 启用/校准 Swagger：分组、版本、授权（Bearer）、描述扩展；输出 swagger.json（CI产物）。
  - 约束：Controller DTO 与 unified-schema 字段完全对齐（已完成基础对齐，持续核验）。
- 前端
  - 引入 NSwag CLI 与配置（nswag.json），生成 TS 客户端至 `@smartabp/lowcode-api`
  - 替换手写 API 调用；统一错误与拦截器；通过 vue-tsc 校验。
- 工具（CLI）
  - 初始化 `lowcode-tools`：`codegen generate --dry-run|--apply`（记录日志/产物目录/时间戳）。
- 验收
  - 前后端 API 类型一致；任意实体的CRUD接口可调用；CI 可产出 swagger.json 与客户端包。

### Week 2 — 后端模板化（P0）+ ts-morph起步 + 增量保护
- 模板清单（Handlebars.Net）
  - Entity（聚合根/拥有者）/ EF 配置 / DTO / AutoMapper Profile / AppService / Controller / Permission 定义
  - 模板准则：命名规范、Helper/Partial 拆分、可配置开关（软删除/多租户/审计）。
- 生成保护
  - C#：partial class/partial method；生成目录：`Generated/*`；用户区：`Custom/*`。
  - TS：引入 ts-morph 覆盖 DTO/Store/路由/API Hooks 的AST生成；落地锚点注释标准。
  - 生成清单 Manifest 记录文件、散列、模板版本；
- 验收
  - dotnet build 通过；生成代码不覆盖用户区；权限/路由/DTO一键可用。

### Week 3 — 质量门禁前置与一致性校验（P0）
- 流水线
  - 生成即检：prettier --write → eslint --max-warnings=0 → vue-tsc --noEmit → dotnet build --verbosity minimal。
- 锚点与Manifest
  - 锚点注释规范：`// <smartabp:region name="X"> ... // </smartabp:region>`（新增：`// <smartabp:user-code>` 与 `// <smartabp:generated>` 保护区）。
  - Manifest（JSON）记录：实体→文件→锚点→版本→哈希；支持 `diff/rollback` 与 three-way merge。
- 一致性校验
  - OpenAPI ↔ NSwag TS Client ↔ 调用端（Store/Views）类型一致性自动比对，发现漂移即失败。
- 验收
  - 生成后流水线全绿；增量再生不覆盖用户区；一致性校验通过。

### Week 4 — VForm3 集成（P1）
- Designer/Renderer 嵌入
  - 绑定 unified-schema 字段配置；双向同步（设计→schema→生成）。
  - 设计器“预览/差异/应用”工作流联动 CLI。
- UI/UX
  - 生成后自动跳转页面验证；错误友好提示；字段完整度评分（zod 校验）。
- 验收
  - 无手工介入下：设计→生成→页面可打开/增删改查可用。

### Week 5 — 快测与体验增强（P0）
- 快测
  - 模板 snapshot & AST compile check（ts-morph 构建后立即类型检查）。
  - 快验收：菜单/路由/权限/页面打开的脚本化校验；契约一致性二次校验。
- 体验
  - （可选）Monaco Editor 集成到 CodePreviewPanel：生成前预览、生成后Diff对比。
- 验收
  - 一键生成自动输出“绿色报告”；失败自动回滚；预览/差异体验可用。

### Week 6 — 性能与规模化（P1）
- 压测
  - 50实体全量生成 < 30s；单实体迭代 < 2s；
  - Manifest 记录对比耗时 < 200ms。
- 稳定性
  - 失败重试/断点续生；生成日志归档与审计。

## 三、关键设计与规范

### 3.1 生成保护与合并策略
- C#：partial class/partial method；生成区 `Generated/*` 与用户区 `Custom/*` 分离。
- TS/Vue：
  - 锚点注释规范（region name 唯一）；非锚点区域完全可覆盖；
  - 生成器只修改受管锚点；用户改动存活于非锚点或“用户区锚点”。
 - 三方合并（three-way merge）与回滚：
   - 合并策略：以 Manifest 记录的上一版本为“共同祖先”，进行 three-way merge；冲突保留用户区优先。
   - 回滚能力：根据 Manifest 版本指针一键回退到最后一次“绿色报告”版本（last-success）。

### 3.2 Manifest（生成清单）规范（示例）
```json
{
  "entity": "Order",
  "version": "1.0.0",
  "files": [
    {
      "path": "src/SmartAbp.Application/Orders/OrderAppService.cs",
      "hash": "e3b0c442…",
      "template": "AppService.hbs",
      "regions": [
        { "name": "imports", "hash": "…" },
        { "name": "custom-methods", "hash": "…", "userEditable": true }
      ]
    }
  ]
}
```

### 3.3 NSwag 配置关键点（示例片段）
```json
{
  "$schema": "https://raw.githubusercontent.com/RicoSuter/NSwag/master/src/NSwag.Commands/configuration.schema.json",
  "runtime": "Net90",
  "documentGenerator": {
    "fromSwagger": { "url": "http://localhost:5000/swagger/v1/swagger.json" }
  },
  "codeGenerators": {
    "openApiToTypeScriptClient": {
      "clientBaseClass": "ApiClientBase",
      "template": "Axios",
      "useAbortSignal": true,
      "httpClass": "AxiosHttp",
      "typeScriptVersion": 5.4,
      "output": "src/SmartAbp.Vue/packages/lowcode-api/src/client.generated.ts"
    }
  }
}
```

### 3.5 Contract-first 工作流（增强）
```yaml
UnifiedSchema（SSOT）
  → 后端 DTO/Controller（字段100%对齐）
  → OpenAPI（Swagger）
  → NSwag 生成 TypeScript Client（@smartabp/lowcode-api）
  → AST生成 Store/路由/API Hooks（ts-morph）
  → 一致性校验（OpenAPI ↔ Client ↔ 调用端）
```

### 3.4 ts-morph 生成范围优先级
- P0：Store/路由/页面骨架/类型守卫
- P1：表单Schema适配器/查询构建器/API hooks
- P2：设计器导入导出适配器/脚手架模板

## 四、质量门禁与验收标准

- 代码级
  - TypeScript：vue-tsc 0错误；ESLint 0警告；Prettier一致；AST生成“生成时类型安全”。
  - C#：dotnet build 成功；无明显警告；可运行 API。
- 业务级
  - 生成后：菜单可点、页面可开、表单可提、数据可查、权限可控。
  - 统一类型：统一 schema ↔ DTO ↔ API 客户端完全一致。
- 运维级
  - CLI 产出报告（绿色/红色）；Manifest 可回滚；日志可追踪。

- 验收准则（Delivery Milestones）：
  - 生成代码编译通过率100%；类型错误为零；用户修改可保护；生成性能达标（50实体<30s，单实体<2s）。

---

## 五、风险与缓解

- 模板/AST 并行复杂度高：C#走 Handlebars，TS关键路径先 ts-morph；严格单一来源和模板评审。
- 设计器引入影响节奏：VForm3 先落地，GrapesJS 延后；以“能用为先、体验跟进”为节奏。
- 大规模生成稳定性：先加 Manifest 与回滚，再做性能压测与断点恢复。

## 附录 B：CLI 命令草案

```bash
# 预览（不落盘），输出差异报告
lowcode-tools codegen generate --entity Order --dry-run

# 应用生成（落盘+质量门禁+报告）
lowcode-tools codegen generate --entity Order --apply

# 生成差异
lowcode-tools codegen diff --entity Order

# 回滚到上一次成功生成
lowcode-tools codegen rollback --entity Order --to last-success
```
