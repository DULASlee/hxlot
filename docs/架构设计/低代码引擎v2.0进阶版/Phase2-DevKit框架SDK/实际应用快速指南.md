# DevKit vs 低代码设计器：实际应用快速指南

## 🚀 1分钟快速决策

### 你应该使用哪个工具？

**如果你是业务分析师/产品经理**:
```
→ 使用 低代码设计器（Web界面）
  ✅ 可视化拖拽设计
  ✅ 实时预览代码
  ✅ 在线协作
```

**如果你是开发者，且需要**:
```
→ 生成1-5个实体 → DevKit CLI 交互式模式
  $ devkit interactive

→ 生成10+个实体 → DevKit CLI 批量模式
  $ devkit batch -i entities.json -o ./output

→ 集成到CI/CD → DevKit CLI（唯一选择）
  $ devkit batch -i $INPUT -o $OUTPUT
```

## 📋 实际项目应用方案

### 方案1: 纯CLI方式（适合开发者）

**适用场景**: 项目初期，需要快速搭建基础代码

```bash
# 第1步：准备实体定义JSON
cat > entities.json << 'EOF'
[
  {
    "entitySchema": {
      "name": "Product",
      "displayName": "产品",
      "properties": [
        {"name": "Id", "type": "Guid", "isKey": true, "isRequired": true, "displayName": "ID"},
        {"name": "Name", "type": "string", "isRequired": true, "displayName": "名称"},
        {"name": "Price", "type": "decimal", "isRequired": true, "displayName": "价格"}
      ]
    }
  }
]
EOF

# 第2步：批量生成
cd <项目根目录>
dotnet run --project tools/SmartAbp.DevKit.Cli -- batch -i entities.json -o ./src/generated -v

# 第3步：查看生成的代码
ls src/generated/
# Product_Generated.cs - 包含Entity/AppService/Controller/DTO

# 第4步：集成到项目
# 复制或移动到实际项目目录
cp src/generated/*.cs src/SmartAbp.Domain/Entities/

# 第5步：添加业务逻辑
# 在生成的代码基础上添加自定义逻辑
```

**时间节省**: **95%** (从3天 → 30分钟)

### 步骤3: 建立标准化生成流程

创建项目级生成脚本：

```bash
# scripts/devkit-generate.sh
#!/bin/bash

set -e

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"
DEVKIT_CLI="$PROJECT_ROOT/src/SmartAbp.DevKit.Cli"
INPUT_FILE="${1:-entities/sprint-current.json}"
OUTPUT_DIR="${2:-./src/generated/$(date +%Y%m%d)}"

echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo "🚀 SmartAbp DevKit代码生成脚本"
echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
echo "📁 输入文件: $INPUT_FILE"
echo "📂 输出目录: $OUTPUT_DIR"
echo ""

# 检查输入文件
if [ ! -f "$INPUT_FILE" ]; then
  echo "❌ 错误：输入文件不存在"
  exit 1
fi

# 创建输出目录
mkdir -p "$OUTPUT_DIR"

# 执行代码生成
echo "🔧 开始生成代码..."
dotnet run --project "$DEVKIT_CLI" -- batch \
  -i "$INPUT_FILE" \
  -o "$OUTPUT_DIR" \
  -v

if [ $? -eq 0 ]; then
  echo ""
  echo "✅ 代码生成成功！"
  echo "📂 生成的文件:"
  ls -lh "$OUTPUT_DIR"
  echo ""
  echo "📝 下一步操作:"
  echo "   1. 检查生成的代码质量"
  echo "   2. 复制到实际项目目录"
  echo "   3. 添加业务逻辑"
else
  echo "❌ 代码生成失败"
  exit 1
fi

echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"
```

使用：
```bash
chmod +x scripts/devkit-generate.sh

# 使用默认输入文件
./scripts/devkit-generate.sh

# 指定输入文件和输出目录
./scripts/devkit-generate.sh entities/module1.json ./src/Module1/Generated
```

## 💡 实际项目示例

### 示例1: 创建一个完整的电商模块

**需求**: 创建Product（产品）、Order（订单）、Customer（客户）三个实体

#### 方法1：使用DevKit CLI（推荐）

```bash
# 1. 创建实体定义
cat > ecommerce-entities.json << 'EOF'
[
  {
    "entitySchema": {
      "name": "Product",
      "displayName": "产品",
      "properties": [
        {"name": "Id", "type": "Guid", "isKey": true, "isRequired": true, "displayName": "ID"},
        {"name": "Name", "type": "string", "isRequired": true, "displayName": "名称"},
        {"name": "Price", "type": "decimal", "isRequired": true, "displayName": "价格"},
        {"name": "Stock", "type": "int", "isRequired": true, "displayName": "库存"}
      ]
    }
  },
  {
    "entitySchema": {
      "name": "Order",
      "displayName": "订单",
      "properties": [
        {"name": "Id", "type": "Guid", "isKey": true, "isRequired": true, "displayName": "ID"},
        {"name": "OrderNo", "type": "string", "isRequired": true, "displayName": "订单号"},
        {"name": "TotalAmount", "type": "decimal", "isRequired": true, "displayName": "总金额"},
        {"name": "OrderDate", "type": "DateTime", "isRequired": true, "displayName": "下单日期"}
      ]
    }
  },
  {
    "entitySchema": {
      "name": "Customer",
      "displayName": "客户",
      "properties": [
        {"name": "Id", "type": "Guid", "isKey": true, "isRequired": true, "displayName": "ID"},
        {"name": "Name", "type": "string", "isRequired": true, "displayName": "姓名"},
        {"name": "Email", "type": "string", "isRequired": true, "displayName": "邮箱"},
        {"name": "Phone", "type": "string", "isRequired": false, "displayName": "电话"}
      ]
    }
  }
]
EOF

# 2. 批量生成
dotnet run --project src/SmartAbp.DevKit.Cli -- batch -i ecommerce-entities.json -o ./output-ecommerce -v

# 3. 查看结果
ls output-ecommerce/
# Product_Generated.cs
# Order_Generated.cs
# Customer_Generated.cs

# 4. 集成到项目（根据需要）
# 后端代码
cp output-ecommerce/*_Generated.cs src/SmartAbp.Domain/Entities/

# 前端代码需要从JSON输出中提取
# （当前版本前端代码输出在日志中，可使用jq提取）
```

**耗时**: **<5分钟**（vs 手写需要2-3小时）

#### 方法2：使用低代码设计器（可视化）

```
1. 打开设计器: http://localhost:5173/lowcode/entity-modeling

2. 可视化创建Product实体
   - 拖拽添加属性
   - 配置类型和验证
   - 实时预览代码

3. 重复创建Order、Customer

4. 导出JSON → ecommerce-entities.json

5. 使用DevKit CLI批量生成（同方法1的第2-4步）
```

**耗时**: **10-15分钟**（可视化操作较慢，但更直观）

## 🎉 核心结论

### 两个工具是互补的，不是竞争的！

```yaml
低代码设计器:
  - 角色: 业务建模工具
  - 用户: 业务人员+开发者
  - 阶段: 设计阶段
  - 输出: 预览+JSON

DevKit CLI:
  - 角色: 代码生产工具
  - 用户: 开发者+CI系统
  - 阶段: 实现阶段
  - 输出: 源代码文件
```

### 黄金法则

```
设计用设计器，生产用DevKit
业务用设计器，开发用DevKit
手工用设计器，自动化用DevKit
协作用设计器，批量用DevKit
```

### 最佳组合

```
低代码设计器（可视化建模）
  +
DevKit CLI（批量生产）
  =
最高效率 + 最优质量 + 最佳协作
```
