## 📋 三、vite.config.ts 配置重复分析

### 3.1 当前配置

```typescript
// vite.config.ts（当前配置）
Components({
  resolvers: [
    ElementPlusResolver(),
    IconsResolver(),
    createPackagesResolver({  // ← 自定义resolver
      packagesRoot: 'packages',
      enableCache: true
    })
  ],
  dirs: [
    'src/components',
    // ⚠️ 以下路径与packagesResolver职责重叠
    'packages/lowcode-shared/src/components',
    'packages/lowcode-core/src/components',
    'packages/lowcode-designer/src/components',
    'packages/lowcode-api/src/components',
    'packages/lowcode-tools/src/components',
    'packages/metadata-core/src/components',
  ],
  deep: true,
  dts: 'components.d.ts'
})
```

### 3.2 重复性分析

```yaml
情况1: 主应用组件（无重复）
  路径: src/components/MyComponent.vue
  机制1 (dirs): ✅ 扫描到
  机制2 (resolver): ❌ 不处理（不在packages中）
  结论: 无重复

情况2: Packages组件（有重复）
  路径: packages/lowcode-core/src/components/LcButton.vue
  机制1 (dirs): ✅ 扫描到（因为dirs包含了packages路径）
  机制2 (resolver): ✅ 也能解析到（通过createPackagesResolver）
  结论: ⚠️ 双重扫描（虽不会冲突，但逻辑不清晰）

问题:
  ⚠️ unplugin-vue-components会先通过dirs扫描packages组件
  ⚠️ 如果dirs没找到，再调用resolver
  ⚠️ 这导致packagesResolver的智能识别（前缀识别）未充分发挥作用
  ⚠️ 两者职责边界模糊
```

### 3.3 优化方案（绝对安全）

```typescript
// ✅ 优化后配置（推荐）
Components({
  resolvers: [
    ElementPlusResolver(),
    IconsResolver(),
    createPackagesResolver({
      packagesRoot: 'packages',
      enableCache: true,
      debug: process.env.NODE_ENV === 'development'
    })
  ],
  // 🎯 只扫描主应用组件
  dirs: ['src/components'],
  deep: true,
  dts: 'components.d.ts',
  exclude: [
    /[\\/]node_modules[\\/]/,
    /[\\/]\.git[\\/]/,
    /[\\/]__tests__[\\/]/,
    /[\\/]examples[\\/]/,
  ]
})
```

**为什么绝对安全？**
1. ✅ `dirs`仍扫描主应用组件（src/components）
2. ✅ `packagesResolver`负责packages组件（职责清晰）
3. ✅ unplugin-vue-components工作流程：
   - 先检查dirs → 找到主应用组件
   - 找不到时调用resolvers → packagesResolver处理
4. ✅ 功能100%保留，只是职责更清晰
