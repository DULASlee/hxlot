## 📊 一、当前机制分析

### 1.1 现状盘点

```yaml
当前存在的组件注册机制:

1. unplugin-vue-components (官方推荐) ✅
   位置: vite.config.ts
   职责: 编译时自动导入组件
   方式: dirs + resolvers
   状态: 正常运行
   
2. packagesResolver (自定义) ✅
   位置: src/utils/vite/packagesResolver.ts
   职责: packages组件路径解析
   方式: ComponentResolver接口
   状态: 正常运行，与unplugin-vue-components集成
   
3. LowCodeComponentsPlugin (应用层) ⚠️
   位置: src/plugins/lowcode-components.ts
   职责: 原为组件注册，现为开发辅助
   方式: Vue plugin (已优化，不再eager注册)
   状态: 已优化，但仍略显冗余
   
4. ComponentRegistry (企业级) ✅
   位置: packages/lowcode-shared/src/components/ComponentRegistry.ts
   职责: 运行时组件管理和沙箱
   方式: 企业级注册中心
   状态: 核心功能完整，但未充分使用

潜在冲突点:
  ⚠️ unplugin-vue-components的dirs配置与packagesResolver职责重叠
  ⚠️ LowCodeComponentsPlugin已优化但略显冗余
  ⚠️ ComponentRegistry功能完整但与编译时机制关联不足
```

## 🎯 二、清理优化方案

### 2.1 核心原则

```yaml
职责分离原则:
  1. 编译时 vs 运行时分离
  2. 主应用 vs packages分离
  3. 静态组件 vs 动态组件分离
  
清晰度原则:
  1. 一个机制只做一件事
  2. 避免职责重叠
  3. 路径明确可追溯
  
性能原则:
  1. Tree-shaking友好
  2. 避免重复扫描
  3. 最小化运行时成本
```

## 🔧 三、具体实施步骤

### Step 1: 清理vite.config.ts中的冗余配置

**问题**: `dirs`配置与`packagesResolver`职责重叠

**解决方案**: 移除`dirs`中的packages路径，完全由`packagesResolver`处理

```typescript
// ❌ 优化前 (vite.config.ts)
Components({
  resolvers: [
    ElementPlusResolver(),
    IconsResolver(),
    createPackagesResolver()
  ],
  dirs: [
    'src/components',
    // ⚠️ 冗余：packages路径应该由resolver处理
    'packages/lowcode-shared/src/components',
    'packages/lowcode-core/src/components',
    'packages/lowcode-designer/src/components',
    'packages/lowcode-api/src/components',
    'packages/lowcode-tools/src/components',
    'packages/metadata-core/src/components',
  ],
  deep: true,
  dts: 'components.d.ts'
})

// ✅ 优化后 (vite.config.ts)
Components({
  resolvers: [
    ElementPlusResolver(),
    IconsResolver(),
    createPackagesResolver({
      packagesRoot: 'packages',
      enableCache: true,
      debug: process.env.NODE_ENV === 'development'
    })
  ],
  // 🎯 只扫描主应用组件目录
  dirs: ['src/components'],
  deep: true,
  dts: 'components.d.ts',
  // 🎯 排除目录配置
  exclude: [
    /[\\/]node_modules[\\/]/,
    /[\\/]\.git[\\/]/,
    /[\\/]__tests__[\\/]/,
    /[\\/]examples[\\/]/,
  ]
})
```

**优势**:
- ✅ 职责清晰：主应用组件由`dirs`扫描，packages组件由`packagesResolver`解析
- ✅ 避免重复：不会扫描packages目录两次
- ✅ 灵活性高：`packagesResolver`可以根据前缀智能解析

### Step 3: 增强ComponentRegistry与编译时机制的集成

**问题**: ComponentRegistry功能完整，但与编译时机制关联不足

**解决方案**: 在组件注册时自动同步到ComponentRegistry

```typescript
// ✅ 增强文件: packages/lowcode-shared/src/components/ComponentRegistry.ts

/**
 * 自动从packages子包收集组件元数据
 * 在应用启动时调用，与编译时机制协同工作
 */
export function collectPackagesComponents(): ComponentMetadata[] {
  const components: ComponentMetadata[] = []
  
  // 从各个package收集组件元数据
  // 这些组件已经被unplugin-vue-components在编译时处理
  // 这里只是收集元数据用于运行时管理
  
  return components
}

/**
 * 初始化组件注册系统
 * 连接编译时和运行时机制
 */
export function initializeComponentSystem() {
  // 1. 收集packages组件元数据
  const packagesComponents = collectPackagesComponents()
  
  // 2. 批量注册到ComponentRegistry
  globalComponentRegistry.registerBatch(packagesComponents)
  
  // 3. 预加载高优先级组件
  globalComponentRegistry.preloadHighPriority()
  
  console.info('[ComponentRegistry] ✅ 组件系统初始化完成')
  console.info(`[ComponentRegistry] 📊 已注册 ${packagesComponents.length} 个组件`)
}
```

```typescript

  // 初始化组件注册系统（运行时）

  // ... 其他初始化代码

}

void bootstrap()
```

**优势**:
- ✅ 编译时和运行时机制协同工作
- ✅ ComponentRegistry可以管理所有组件的元数据
- ✅ 支持运行时动态加载和沙箱隔离

### Step 4: 更新packagesResolver，增强智能识别

**优化点**: 增强组件路径解析的智能性和容错性

```typescript
// ✅ 优化文件: src/utils/vite/packagesResolver.ts

/**
 * 解析组件文件路径（增强版）
 */
function resolveComponentPath(
    packagesRoot: string,
    packageName: string,
    componentBaseName: string
): string | null {
    const searchPaths = [
        // 1. 标准路径: components/${ComponentName}.vue
        resolve(packagesRoot, packageName, 'src', 'components', `${componentBaseName}.vue`),

        // 2. 索引文件: components/${ComponentName}/index.vue
        resolve(packagesRoot, packageName, 'src', 'components', componentBaseName, 'index.vue'),

        // 3. kebab-case目录: components/${component-name}/${ComponentName}.vue
        resolve(packagesRoot, packageName, 'src', 'components', kebabCase(componentBaseName), `${componentBaseName}.vue`),
        
        // 4. 嵌套目录: components/*/${ComponentName}.vue (深度搜索)
        // 注：性能考虑，可选择性启用
    ]

    for (const path of searchPaths) {
        if (existsSync(path)) {
            // ✅ 返回别名路径，符合Vite alias配置
            // 格式: @smartabp/${packageName}/src/components/${componentBaseName}
            return `@smartabp/${packageName}/src/components/${componentBaseName}`
        }
    }

    return null
}

/**
 * 导出缓存管理工具（供Vite plugin使用）
 */
export function clearComponentPathCache(): void {
    componentPathCache.clear()
    console.info('[PackagesResolver] 🧹 缓存已清理')
}

export function getCacheStats(): {
    size: number
    keys: string[]
} {
    return {
        size: componentPathCache.size,
        keys: Array.from(componentPathCache.keys())
    }
}
```
