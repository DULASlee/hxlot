## 目标与范围

本手册面向架构师与一线开发者，系统性说明 SmartAbp 统一元数据模型驱动的代码生成（以下简称“元数据代码生成”）的技术架构、目录与组件、运行流程、操作指引与常见问题。读完本文，您将能够：

- 理解元数据→验证→代码生成的端到端架构
- 正确编写实体元数据并通过校验
- 使用 CLI 一键生成前端代码（后端生成器提供占位与对接点）
- 排查常见问题并掌握约定与最佳实践

## 核心价值

- **一致性**：以统一元数据模型为单一事实来源（SSOT），前后端按同一套语义生成与演进。
- **提效**：面向实体的标准页面/接口可在分钟级完成，显著降低重复劳动。
- **类型安全**：Zod 运行时校验 + TypeScript 类型推导，降低接口契约偏差风险。
- **可演进**：语义版本化（SemVer）与兼容性检测，支撑安全升级与差异追踪。

## 总体架构

### 架构分层

1. 元数据定义层（Schema-First）
   - 目录：`hxlot/metadata/entities/**.metadata.ts`
   - 工件：`EntityMetadata`/`ModuleMetadata`

2. 元数据校验层（@smartabp/metadata-core）
   - 包路径：`hxlot/src/SmartAbp.Vue/packages/metadata-core`
   - 组件：`validators/*`、`types/*`、`converters/*`
   - 能力：Zod Schema、跨字段校验、错误映射、自定义规则

3. 代码生成层（CLI）
   - 入口：`src/tools/metadata-codegen.ts`
   - 生成器：`src/tools/generators/frontend-generator.ts`、`backend-generator.ts`
   - 输出：前端 `.ts/.vue`、后端占位（后续对接 AppService）

4. 运行支撑与标准化
   - NPM 脚本：`codegen:entity|frontend|backend|all`
   - 质量：Deep Test/Iron Law（已在核心校验与模板中固化）

### 数据流与控制流

1) 读取 CLI 参数 → 2) 解析并定位实体元数据文件 → 3) 动态导入实体元数据 → 4) 调用 `@smartabp/metadata-core` 校验 → 5) 分发至前/后端生成器 → 6) 渲染模板并写入文件（或 dry-run 列表）

## 目录结构（关键路径）

```
hxlot/
  metadata/

      library/book.metadata.ts       # 示例实体元数据（Book）
  src/SmartAbp.Vue/

    src/tools/

        backend-generator.ts         # 后端生成器（占位）
    packages/metadata-core/          # 元数据核心库（types/validators/...）
```

## 元数据模型（概要）

- `EntityMetadata`（关键字段）
  - `name`（PascalCase）、`module`、`keyType`（Guid/int/long/string）
  - `properties`：字段集合（name、type、required、maxLength...）
  - `navigationProperties`：关系（关系类型、目标实体、foreignKey 等）
  - `xUiConfig` / `xBackendConfig`：可选的前后端生成定制

示例：

```ts
export const BookMetadata = {
  schemaVersion: '1.0.0',
  name: 'Book',
  module: 'library',
  keyType: 'Guid',
  isAggregateRoot: true,
  isMultiTenant: false,
  isSoftDelete: true,
  hasExtraProperties: true,
  properties: [
    { name: 'title', type: 'string', isRequired: true, maxLength: 256, description: '图书标题' },
    { name: 'isbn', type: 'string', isRequired: true, maxLength: 32, description: '国际标准书号' },
    { name: 'author', type: 'string', isRequired: true },
    { name: 'publisher', type: 'string', isRequired: false },
    { name: 'publishDate', type: 'string', isRequired: false },
    { name: 'price', type: 'number', isRequired: true },
    { name: 'stock', type: 'number', isRequired: true }
  ]
} as const
```

## 校验规则（精选）

- 字段命名：属性 camelCase、实体 PascalCase
- 字符串长度：`maxLength` 合理区间（>0 且 ≤ 10000）
- 关系校验：在仅有 `id` 属性的特殊场景下，`foreignKey` 会被严格校验（其余情况允许 ORM 管理）
- 路由/模块校验：顶层路由需以 `/` 开头，嵌套路由允许相对路径；路由名允许下划线

## 代码生成器设计

### CLI 入口（metadata-codegen.ts）

- 参数解析：`frontend|backend|all` + `--entity/-e` + `--dry-run/-d` + `--output/-o`
- 元数据发现：`hxlot/metadata/entities/**/*.metadata.ts` 递归匹配
- 动态导入：使用 `file://` URL 规避 Windows 路径差异
- 校验：调用 `validateEntityMetadataAsync`
- 分发：前端/后端生成器

### 前端生成器（frontend-generator.ts）

- 生成内容：
  - `book.types.ts`（DTO/Request/Result）
  - `book-api.ts`（REST API 封装）
  - `BookList.vue`（列表/搜索/分页）
  - `BookForm.vue`（表单/校验）
  - `BookDetail.vue`（详情）
  - `useBookStore.ts`（Pinia Store）
- 输出路径：`src/views/<module>/<entity>/...`、`src/stores/<module>/...`

### 后端生成器（backend-generator.ts）

- 当前提供占位实现与对接点（建议对接 CodeGenerationAppService）
- 规划输出：C# 实体、DTO、AppService、Controller、Mapping 等

## 安装与运行

### 先决条件

- Node.js ≥ 18
- 在工作区根目录执行（已配置 npm workspace）
- 构建 `metadata-core`：

```bash
cd hxlot/src/SmartAbp.Vue/packages/metadata-core && npm run build
```

### NPM 脚本（推荐）

```bash
# 仅前端
npm run codegen:frontend -- --entity=Book

# 仅后端（占位）
npm run codegen:backend -- --entity=Book

# 全部（前+后端）
npm run codegen:all -- --entity=Book

# 预览（不落盘）
npm run codegen:frontend -- --entity=Book --dry-run
```

说明：若遇到 npm 参数透传告警，可直接使用 tsx 运行（等效）：

```bash
npx tsx src/tools/metadata-codegen.ts frontend --entity Book --dry-run
```

## 约定与最佳实践

- 文件命名：`<entity>.metadata.ts`，例如 `book.metadata.ts`
- 目录分组：按业务域组织，如 `entities/library/`
- 实体命名：统一 PascalCase，属性 camelCase
- 注释与描述：充分填写 `description`，直接进入前端表单/详情
- 逐步细化：先生成标准骨架，再按需在模板基础上微调

## 常见问题（FAQ）

1. 运行时报找不到 `@smartabp/metadata-core`？
   - 采用稳定方案：CLI 内部当前从 `packages/metadata-core/dist/index.js` 导入。
   - 若需包名导入，请确保 tsx 读取 tsconfig paths 或发布到私有/本地 npm registry。

2. Windows 下动态导入 `.ts` 失败？
   - CLI 使用 `file://` URL 导入已修复；请确保路径无中文与空格（或保持一致编码）。

3. 生成的是 JS 还是 TS？
   - 生成产物均为 `.ts`/`.vue`。CLI 源码对 `dist` 的 `.js` 引用仅为稳定运行所需，不影响输出类型。

4. npm 透传参数出现告警（Unknown cli config）？
   - 可改用 `npx tsx ...` 形式；或升级 npm 并使用 `--` 分隔。
