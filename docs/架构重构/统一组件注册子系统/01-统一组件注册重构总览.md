# 统一组件注册重构总览

## 背景与目标
- 现状问题：组件注册分散、多入口并存、注册中心未被使用、路径别名不一致、类型与组件体系缺乏统一门禁。
- 重构目标：建立“单一且严格”的统一组件注册子系统，确保全项目组件通过`ComponentRegistry`集中注册与按需加载，三处配置（tsconfig/vite/eslint）严格一致，并形成质量门禁脚本与Git钩子保障。

## 重构范围
- 包含：`lowcode-shared`、`lowcode-core`、`lowcode-designer`、主应用`src/SmartAbp.Vue`。
- 不包含：后端与非低代码相关子系统功能。

## 关键产出
- 统一注册链路：`registerSharedComponents -> registerCoreComponents -> registerDesignerComponents`，在主应用`src/main.ts`按顺序调用。
- 自动补全注册：为`core`/`designer`增加基于`import.meta.glob`的自动扫描与可选`loader`回调。
- 组件注册检查器：`check-component-registration`确保所有组件处于统一注册范畴。
- 配置一致性检查器（严格）：`check-config-consistency`严格比对`tsconfig.json`、`vite.config.ts`、`.eslintrc.cjs`与`smartabp.config.json`期望一致。
- 检查器集中与聚合：集中于`packages/quality-guardian/checkers/`，新增`check:all`聚合入口，`pre-commit`强制执行。

## 量化成果
- 启动验证：Vite开发服务器正常启动，统一注册链路日志输出正常。
- 检查通过：`npm run check:all`严格模式零错误通过。
- 架构一致性：别名、规则、注册入口均统一并可持续校验。

## 后续建议
- 将其他代码质量/依赖/循环依赖检查逐步迁移到集中目录。
- 为`ComponentRegistry`增加更细粒度性能测量与报表输出。
