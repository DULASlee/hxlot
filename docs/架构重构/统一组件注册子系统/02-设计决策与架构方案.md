# 设计决策与架构方案

## 决策1：强制单一注册中心
- 方案：所有低代码组件必须通过`@smartabp/lowcode-shared`的`ComponentRegistry`注册；禁止分散导出/直接import组件文件使用。
- 权衡：牺牲少量直接导入便捷性，换取可治理、可观测、可度量的一致性组件体系。

## 决策2：集中注册函数与自动补全
- 核心：
  - `lowcode-shared`: `registerSharedComponents()`
  - `lowcode-core`: `registerCoreComponents()` + 自动扫描`components/**/*.vue`并提供`loader`
  - `lowcode-designer`: `registerDesignerComponents()` + 自动扫描`components|views|runtime/**/*.vue`并提供`loader`
- 目的：杜绝漏注册与入口分散，确保新加组件即受统一门禁保护。

## 决策3：别名与规则严格一致
- 约束：
  - `tsconfig.json` `paths`严格映射`smartabp.config.json`的期望
  - `vite.config.ts` 别名必须映射到`packages/<pkg>[/src]`
  - `.eslintrc.cjs` 必须包含：禁止`@smartabp/*/src/*`、禁止`**/packages/**`相对路径引用
- 理由：减少AI/人工作业歧义，统一路径认知模型。

## 决策4：质量门禁集中化
- 位置：`src/SmartAbp.Vue/packages/quality-guardian/checkers/`
- 入口：
  - `check-config-consistency.js`（严格）
  - `check-component-registration.js`
  - `check-all.js`（聚合）
- Git钩子：pre-commit 强制运行`npm run check:all`。

## 决策5：按需动态加载与性能
- 在注册元数据中支持可选`loader`回调，结合`import.meta.glob`进行懒加载。
- 原因：大规模组件库的首屏加载与内存占用可控。

## 决策6：无侵入回退策略
- 若动态导入失败，返回占位组件并打印告警；不阻塞应用运行，便于灰度推进。
