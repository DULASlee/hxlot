# 质量门禁与检查器说明

## 严格一致性规则
- `tsconfig.json`：每个`@smartabp/<pkg>`与`@smartabp/<pkg>/*`必须精确映射到`smartabp.config.json`期望路径（`packages/<pkg>/src/index.ts`与`packages/<pkg>/src/*`或无src变体）。
- `vite.config.ts`：别名必须存在且映射至`packages/<pkg>[/src]`。
- `.eslintrc.cjs`：
  - 禁止`@smartabp/*/src/*`导入（必须用包别名顶层入口）。
  - 禁止相对路径引用`**/packages/**`（必须使用`@smartabp/*`）。

## 检查器集中位置
- 目录：`src/SmartAbp.Vue/packages/quality-guardian/checkers/`
- 文件：
  - `check-config-consistency.js`（严格，文本级匹配，避免JSON解析不稳定）
  - `check-component-registration.js`（统一注册覆盖校验）
  - `check-all.js`（聚合）

## 运行方式
- 本地手动：
  - `npm run check:config`
  - `npm run check:components`
  - `npm run check:all`
- 提交门禁：`.husky/pre-commit` 自动执行 `npm run check:all`，不通过阻断提交。

## 常见失败原因与修复
- 别名路径不一致：修改`tsconfig.json`或`vite.config.ts`以映射至`smartabp.config.json`期望。
- 缺少ESLint规则：在`.eslintrc.cjs`的`no-restricted-imports`中补充禁止规则。
- 漏注册组件：补充相应`register*Components()`或opt-in `import.meta.glob`扫描。

## 成功标准
- `npm run check:all`稳定通过。
- 提交时 pre-commit 门禁稳定通过。
- 组件实际运行按需加载正常，未出现直接路径导入组件的现象。
