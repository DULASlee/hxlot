# SmartAbp运维监测系统 - 操作使用说明

## 1. 系统登录与访问

### 1.1 访问地址

**生产环境**
- URL: https://ops.smartabp.com
- 端口: 443 (HTTPS)
- 认证: JWT Token（从主应用获取）

**开发环境**
- URL: http://localhost:8080
- 端口: 8080 (HTTP)
- Swagger文档: http://localhost:8080/swagger

**前端访问**
- 生产环境: https://smartabp.com/ops-monitoring
- 开发环境: http://localhost:3000/ops-monitoring

### 1.2 权限要求

访问运维监测系统需要以下权限：
- `OpsManagement.Metrics.View` - 查看性能监控
- `OpsManagement.Logs.View` - 查看日志管理
- `OpsManagement.K8s.View` - 查看K8s监控
- `OpsManagement.Alerts.Manage` - 管理告警规则

管理员账号默认拥有所有权限。

## 2. APM性能监控面板

### 2.1 访问路径

主菜单 → 运维监控 → 性能监控

### 2.2 功能说明

**实时指标卡片**
- **CPU使用率**: 显示当前服务CPU占用百分比，超过80%显示警告色
- **内存使用率**: 显示当前内存占用百分比，超过85%显示警告色
- **请求数/秒**: 实时请求处理速率，带趋势箭头指示
- **平均响应时间**: API平均响应时间（毫秒），越低越好

**趋势图表**
- **CPU & 内存趋势图**: 最近24小时的CPU和内存使用曲线，鼠标悬停显示具体数值
- **请求响应时间趋势**: P50/P95/P99响应时间对比，帮助识别性能瓶颈

**服务性能摘要表格**
- 列出所有微服务的性能汇总
- 支持按CPU、内存、响应时间排序
- 点击服务名可查看详细历史数据

### 2.3 操作步骤

**1. 选择服务**
```
下拉框选择要监控的服务 → SmartAbp.Web / SmartAbp.CodeGenerator / SmartAbp.OpsManagement
```

**2. 选择时间范围**
```
下拉框选择时间范围 → 最近1小时 / 6小时 / 24小时 / 7天
```

**3. 刷新数据**
```
点击"刷新"按钮 → 立即获取最新数据
自动刷新：每30秒自动更新一次
```

**4. 查看趋势**
```
鼠标悬停在图表上 → 查看具体时间点的数值
拖动图表 → 缩放时间范围
```

### 2.4 告警阈值

系统预设告警阈值：
- CPU使用率 > 80%: 警告
- 内存使用率 > 85%: 警告
- 平均响应时间 > 500ms: 警告
- 请求错误率 > 5%: 严重

## 3. ELK日志管理面板

### 3.1 访问路径

主菜单 → 运维监控 → 日志管理

### 3.2 功能说明

**日志统计卡片**
- 总日志数：当前时间范围内的日志总数
- 错误日志：Error级别日志数量
- 警告日志：Warning级别日志数量
- 错误率：错误日志占比

**可视化图表**
- **日志级别分布饼图**: Debug/Info/Warning/Error/Fatal分布比例
- **日志趋势图**: 最近24小时各级别日志数量趋势

**日志查询表单**
- 服务名称：筛选指定服务的日志
- 日志级别：Debug/Information/Warning/Error/Fatal
- 关键词：全文搜索日志内容
- 时间范围：起止时间段选择

**日志列表**
- 时间：日志产生时间（精确到秒）
- 级别：带颜色标签的日志级别
- 服务：产生日志的服务名称
- 消息：日志内容摘要（鼠标悬停查看完整内容）
- TraceID：分布式追踪ID（可追踪完整请求链路）
- 操作：点击"详情"查看完整日志信息

### 3.3 操作步骤

**1. 基础查询**
```
1. 选择服务名称（可选）
2. 选择日志级别（可选）
3. 输入关键词（可选）
4. 选择时间范围（默认最近1小时）
5. 点击"查询"按钮
```

**2. 高级查询**
```
组合条件查询：
- 服务名称 = "SmartAbp.Web" 
- 日志级别 = "Error"
- 关键词 = "database timeout"
- 时间范围 = 最近24小时

支持空值查询：不选择任何条件，查询所有日志
```

**3. 查看日志详情**
```
点击日志行的"详情"按钮 → 弹出对话框显示：
- 完整时间戳
- 日志级别
- 服务名称
- TraceID（用于追踪完整请求链路）
- 请求路径
- 完整日志消息
- 异常堆栈信息（如果有）
```

**4. 分页浏览**
```
底部分页器：
- 每页显示：10/20/50/100条可选
- 总数统计：显示符合条件的日志总数
- 页码跳转：支持快速跳转到指定页
```

### 3.4 常见查询场景

**查找错误日志**
```
服务名称：（留空，查所有服务）
日志级别：Error
关键词：（留空）
时间范围：最近1小时
```

**查找特定服务的警告**
```
服务名称：SmartAbp.CodeGenerator
日志级别：Warning
关键词：（留空）
时间范围：最近6小时
```

**追踪特定请求**
```
服务名称：（留空）
日志级别：（留空）
关键词：<粘贴TraceID>
时间范围：最近24小时
```

**排查数据库问题**
```
服务名称：（留空）
日志级别：Error
关键词：database 或 timeout 或 connection
时间范围：最近1小时
```

## 4. K8s资源监控面板

### 4.1 访问路径

主菜单 → 运维监控 → K8s监控

### 4.2 功能说明

**集群摘要卡片**
- 节点总数：K8s集群节点数量
- Pod总数：运行中的Pod数量
- CPU使用率：集群平均CPU使用率
- 内存使用率：集群平均内存使用率

**资源Tab切换**
- **Pods**: 查看和管理Pod资源
- **Deployments**: 查看和管理Deployment资源
- **Services**: 查看Service资源

**Pods列表**
- Pod名称：完整的Pod名称
- 命名空间：所属命名空间
- 状态：Running/Pending/Failed/Unknown
- CPU使用：当前CPU占用百分比
- 内存使用：当前内存占用百分比
- 重启次数：Pod重启计数
- 运行时长：Pod已运行时间
- 操作：查看日志、重启Pod

**Deployments列表**
- Deployment名称
- 命名空间
- 副本数：就绪副本/期望副本（如 3/3）
- 可用副本：当前可用的副本数
- 创建时长：Deployment创建时间
- 操作：扩缩容

**Services列表**
- Service名称
- 命名空间
- 类型：ClusterIP/NodePort/LoadBalancer
- Cluster IP：内部集群IP
- External IP：外部访问IP（如果有）
- 端口：端口映射配置
- 创建时长

### 4.3 操作步骤

**1. 查看集群资源**
```
选择命名空间 → default / kube-system / smartabp
点击"刷新"按钮 → 获取最新资源状态
```

**2. 查看Pod日志**
```
1. 切换到"Pods" Tab
2. 找到目标Pod
3. 点击"查看日志"按钮
4. 在弹出的日志窗口中：
   - 搜索关键词
   - 开启/关闭自动滚动
   - 点击"下载日志"保存到本地
```

**3. 重启Pod**
```
1. 找到需要重启的Pod
2. 点击"重启"按钮
3. 确认重启操作
4. 等待Pod重启完成（自动刷新状态）
```

**4. Deployment扩缩容**
```
1. 切换到"Deployments" Tab
2. 找到目标Deployment
3. 点击"扩缩容"按钮
4. 输入期望副本数（如 5）
5. 确认操作
6. 观察副本数变化
```

### 4.4 状态说明

**Pod状态**
- Running（绿色）：正常运行
- Pending（黄色）：等待调度或拉取镜像
- Failed（红色）：启动失败或崩溃
- Unknown（灰色）：状态未知，可能节点失联

**重启次数解读**
- 0次：Pod稳定运行，无重启
- 1-3次：可能发生过临时问题，已恢复
- >3次：频繁重启，需要排查根因

## 5. 智能告警管理面板

### 5.1 访问路径

主菜单 → 运维监控 → 告警管理

### 5.2 功能说明

**告警规则列表**
- 规则名称：自定义规则名称
- 指标类型：CpuUsage/MemoryUsage/ApiResponseTime/ErrorRate/RequestCount
- 触发条件：操作符 + 阈值（如 > 80）
- 严重级别：Info/Warning/Critical
- 目标资源：监控的服务或资源
- 状态：启用/禁用开关
- 操作：编辑、删除

**告警历史时间线**
- 按时间倒序展示所有告警记录
- 每条告警包含：
  - 时间戳
  - 严重级别标签
  - 告警标题
  - 详细消息
  - 来源服务
  - 查看详情链接

### 5.3 操作步骤

**1. 创建告警规则**
```
1. 点击"创建告警规则"按钮
2. 填写表单：
   - 规则名称：如"CPU使用率过高告警"
   - 指标类型：选择"CPU使用率"
   - 触发条件：选择"> 80"
   - 严重级别：选择"Warning"
   - 目标资源：如"SmartAbp.Web"或"*"（所有服务）
   - 通知渠道：勾选"邮件"、"钉钉"
3. 点击"确定"保存规则
```

**2. 编辑告警规则**
```
1. 找到要编辑的规则
2. 点击"编辑"按钮
3. 修改规则参数
4. 点击"确定"保存
```

**3. 启用/禁用规则**
```
直接点击规则行的开关按钮
- 绿色开启：规则已启用，正在监控
- 灰色关闭：规则已禁用，不会触发告警
```

**4. 删除告警规则**
```
1. 点击"删除"按钮
2. 确认删除操作
3. 规则被永久删除
```

**5. 搜索规则**
```
在搜索框输入关键词 → 实时过滤规则列表
支持按规则名称模糊搜索
```

**6. 查看告警历史**
```
页面下方的时间线展示所有历史告警
点击"查看详情"可查看告警的完整信息
```

### 5.4 告警规则配置示例

**CPU使用率告警**
```yaml
规则名称: CPU使用率过高
指标类型: CpuUsage
操作符: >
阈值: 80
严重级别: Warning
目标资源: *
通知渠道: [邮件, 钉钉]
```

**内存使用率告警**
```yaml
规则名称: 内存使用率告警
指标类型: MemoryUsage
操作符: >
阈值: 85
严重级别: Critical
目标资源: SmartAbp.CodeGenerator
通知渠道: [邮件, 短信, Webhook]
```

**API响应时间告警**
```yaml
规则名称: API响应时间过长
指标类型: ApiResponseTime
操作符: >
阈值: 500
严重级别: Warning
目标资源: *
通知渠道: [邮件]
```

**错误率告警**
```yaml
规则名称: 错误率异常
指标类型: ErrorRate
操作符: >
阈值: 5
严重级别: Critical
目标资源: SmartAbp.Web
通知渠道: [邮件, 短信, 钉钉, Webhook]
```

### 5.5 通知渠道配置

**邮件通知**
- SMTP服务器：在Secret中配置
- 收件人：支持多个邮箱地址
- 模板：支持自定义邮件模板

**短信通知**
- 短信网关：支持阿里云、腾讯云等
- 接收手机号：支持多个号码
- 模板：预设告警短信模板

**钉钉通知**
- Webhook URL：在Secret中配置
- @人员：支持@特定人员或@all
- 消息类型：Markdown格式

**Webhook通知**
- URL：自定义Webhook地址
- 请求方式：POST
- 数据格式：JSON
- 重试机制：失败自动重试3次
