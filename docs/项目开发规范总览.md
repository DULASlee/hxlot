## 🔥 架构三大铁律（优先级-2，最高）

### 铁律一：强制使用统一类型系统
```yaml
规则:
  ✅ 所有类型在 lowcode-shared/types 定义
  ❌ 禁止主应用定义底层类型
  ❌ 禁止相对路径导入类型
  ❌ 禁止每个文件重复定义类型

检测:
  find src/core -name "*types.ts" -o -name "*types.d.ts"
  grep -r "from '\.\./.*types" src/
  
修复:
  1. 删除主应用中的类型文件
  2. 在 lowcode-shared/types 中创建正确类型
  3. 使用 @smartabp/lowcode-shared 导入

违反处罚: 💀 立即删除，重新实现
```

### 铁律二：强制使用组件注册系统
```yaml
规则:
  ✅ 所有组件必须注册到 ComponentRegistry
  ✅ 提供完整的 ComponentMetadata
  ✅ 声明所有依赖关系
  ❌ 禁止跳过注册直接使用
  ❌ 禁止硬编码组件路径

检测:
  find packages/*/src/components -name "*.vue"
  grep -r "registerComponent" packages/*/src/
  
修复:
  1. 在 ComponentRegistry 注册组件
  2. 补充完整的 ComponentMetadata
  3. 通过 loadComponent() 加载使用

违反处罚: 💀 立即补充注册，否则删除
```

### 铁律三：严格遵循架构层级
```yaml
规则:
  ✅ 只能向下依赖（Layer 2→1→0→-1）
  ✅ 使用 @smartabp/* 别名
  ❌ 禁止逆向依赖
  ❌ 禁止跨层级引用
  ❌ 禁止主应用定义底层类型

架构层级:
  Layer 2: lowcode-designer
  Layer 1: lowcode-core, lowcode-api, lowcode-tools
  Layer 0: lowcode-shared
  Layer -1: metadata-core
  主应用 (src/): 只使用，不定义

检测:
  grep -r "@smartabp/lowcode-core" packages/lowcode-shared/
  grep -r "@smartabp/lowcode-designer" packages/lowcode-core/
  grep -r "'\.\./" packages/*/src/
  
修复:
  1. 删除主应用中的底层类型定义
  2. 将类型移至正确的 package
  3. 修复所有依赖关系

违反处罚: 💀 架构违规，格杀勿论
```

## 任务分级响应

### Level 1: 微小任务（<20行代码）
- 快速理解 → 直接修改 → TypeScript检查
- 时间: <2分钟

### Level 2: 中等任务（20-200行）
- 理解需求 → 检索现有实现 → 简要分析 → 编码 → 质量检查
- 时间: 5-15分钟

### Level 3: 重大任务（>200行）
- 深度分析（15节点） → 业界搜索 → 用户确认 → 分步实现 → 质量门禁
- 时间: 20-60分钟
