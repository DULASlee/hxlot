## 🎯 为什么需要项目架构指南？

### 问题背景

```yaml
AI面临的挑战:
  ❌ 不了解项目特有的架构模式
  ❌ 不知道ComponentRegistry组件注册系统
  ❌ 不理解元数据驱动的开发模式

  - 创建组件不注册 → 组件无法被发现
```


## 📚 项目架构指南内容概览

### 第1章：核心架构三大支柱

#### 支柱1：企业级组件注册系统

```typescript
// AI将学会如何正确注册和使用组件
import { registerComponent, ComponentMetadata } from '@smartabp/lowcode-shared'

registerComponent({
  name: 'SmartFormBuilder',
  displayName: '智能表单构建器',
  category: 'form',
  priority: 'high',
  dependencies: ['BaseComponent'],
  bundle: '@smartabp/lowcode-core',
  lazy: true,
  version: '1.0.0'
})
```

**AI将知道**:
- ✅ 创建组件必须注册
- ✅ 如何提供完整的ComponentMetadata
- ✅ 如何声明依赖关系
- ✅ 如何设置加载优先级
- ❌ 禁止不注册直接使用

#### 支柱2：元数据驱动的统一类型系统

```typescript
// AI将学会基于元数据开发
import type { EntityMetadata } from '@smartabp/metadata-core'
import { validateEntityMetadata } from '@smartabp/metadata-core'

const BookMetadata: EntityMetadata = {
  name: 'Book',
  module: 'Library',
  keyType: 'Guid',
  properties: [/* ... */]
}

const validated = validateEntityMetadata(BookMetadata)

// 使用元数据生成代码
await codeGenStore.generateCode({ entities: [validated] })
```

**AI将知道**:
- ✅ 定义实体使用EntityMetadata
- ✅ 实体名PascalCase，属性名camelCase
- ✅ 必须通过验证
- ✅ 从元数据生成代码，不手写DTO
- ❌ 禁止前后端类型不一致

#### 支柱3：Packages独立组件架构

```
Layer 2: lowcode-designer
  ↓
Layer 1: lowcode-core, lowcode-api, lowcode-tools
  ↓
Layer 0: lowcode-shared
  ↓
Layer -1: metadata-core
```

**AI将知道**:
- ✅ 使用@smartabp/别名引用
- ✅ 只能依赖更低层级的package
- ❌ 禁止相对路径（../）跨package引用
- ❌ 禁止@/引用主应用（在packages中）
- ❌ 禁止逆向依赖

```typescript
// ✅ 场景1: 完整的组件创建流程
// 1. 创建组件
// src/SmartAbp.Vue/packages/lowcode-core/src/components/NewComponent.vue

// 2. 导出组件
export { default as NewComponent } from './NewComponent.vue'

// 3. 注册组件
import { registerComponent } from '@smartabp/lowcode-shared'

registerComponent({
  name: 'NewComponent',
  displayName: '新组件',

  priority: 'medium',

const BookMetadata: EntityMetadata = {
  name: 'Book',
  module: 'Library',
  keyType: 'Guid',
  properties: [/* ... */]
}

// 2. 验证元数据
const validated = validateEntityMetadata(BookMetadata)

// 3. 生成代码
await codeGenStore.generateCode({ entities: [validated] })

// 结果：前后端类型一致，自动生成完整CRUD

// ✅ 场景3: 正确的跨package引用
```

## 🎯 使用建议

### 对于AI

```yaml
执行流程:
  1. 接收任务后，首先回忆项目架构三大支柱
  2. 确定代码应该在哪个package中
  3. 如果涉及组件，使用ComponentRegistry
  4. 如果涉及实体，使用元数据驱动方式
  5. 跨package引用时检查依赖层级
  6. 完成后运行架构合规检查

检查命令:
  # 架构合规检查
  grep -r "'../'" src/SmartAbp.Vue/packages/
  grep -r "@/" src/SmartAbp.Vue/packages/
  
  # TypeScript检查
  cd src/SmartAbp.Vue && npx tsc --build tsconfig.references.json
  
  # ESLint检查
  cd src/SmartAbp.Vue && npm run lint -- "packages/*/src/**/*.{ts,vue}"
```

### 对于用户

```yaml
任务描述时可以提及:
  - "创建一个组件并正确注册"
  - "基于元数据生成Book实体的CRUD页面"
  - "在lowcode-designer中添加XX功能"
  
这样AI会自动应用架构指南中的最佳实践
```
