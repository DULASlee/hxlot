## 概述

### 为什么需要组件命名规范？

在Monorepo + packages黑盒架构中，统一的组件命名规范可以：

- ✅ **避免组件名冲突**：不同package中可能存在同名组件
- ✅ **提升代码可读性**：通过前缀快速识别组件来源
- ✅ **增强IDE智能提示**：TypeScript类型提示更精准
- ✅ **简化组件引用**：零导入，直接在template使用

### 设计理念

参考业界标准（Element Plus的`El`前缀），我们为每个package定义专属前缀：

- **lowcode-shared**: `Ls` (Lowcode Shared)
- **lowcode-core**: `Lc` (Lowcode Core)
- **lowcode-designer**: `Ld` (Lowcode Designer)
- **lowcode-api**: `La` (Lowcode Api)
- **lowcode-tools**: `Lt` (Lowcode Tools)
- **metadata-core**: `Mc` (Metadata Core)

## 命名规范

### 基本规则

1. **PascalCase命名**（大驼峰）
   ```
   ✅ MyComponent.vue
   ✅ UserProfile.vue
   ❌ myComponent.vue (错误)
   ❌ user-profile.vue (错误)
   ```

2. **语义化命名**
   ```
   ✅ UserProfileCard.vue (明确含义)
   ✅ DataTable.vue (清晰简洁)
   ❌ Comp1.vue (无意义)
   ❌ Temp.vue (临时命名)
   ```

3. **单一职责**
   ```
   ✅ UserAvatar.vue (只负责头像)
   ✅ UserBadge.vue (只负责徽章)
   ❌ UserAvatarAndBadge.vue (职责过多)
   ```

### 命名长度建议

- **最短**: 2个单词 (如`DataTable`)
- **最长**: 4个单词 (如`UserProfileEditForm`)
- **超过4个单词**: 考虑拆分组件或重新命名

## 组件前缀规则

### Packages组件前缀

| Package | 前缀 | 示例 | 说明 |
|---------|------|------|------|
| **lowcode-shared** | `Ls` | `LsButton.vue` | 低代码共享组件库 |
| **lowcode-core** | `Lc` | `LcCanvas.vue` | 低代码核心组件 |
| **lowcode-designer** | `Ld` | `LdToolbar.vue` | 低代码设计器组件 |
| **lowcode-api** | `La` | `LaClient.vue` | 低代码API组件 |
| **lowcode-tools** | `Lt` | `LtValidator.vue` | 低代码工具组件 |
| **metadata-core** | `Mc` | `McSchema.vue` | 元数据核心组件 |

### 主应用组件（无前缀）

主应用`src/components`下的组件**不使用前缀**：

```
✅ src/components/Button.vue
✅ src/components/UserCard.vue
❌ src/components/AppButton.vue (不需要前缀)
```

### 前缀使用示例

**lowcode-shared包**:
```vue
<!-- packages/lowcode-shared/src/components/Button.vue -->
<script setup lang="ts">
// 组件逻辑
</script>

<!-- 使用时（零导入） -->
<template>
  <LsButton type="primary">确定</LsButton>
</template>
```

**lowcode-core包**:
```vue
<!-- packages/lowcode-core/src/components/Canvas.vue -->
<script setup lang="ts">
// 画布组件逻辑
</script>

<!-- 使用时（零导入） -->
<template>
  <LcCanvas :config="canvasConfig" />
</template>
```

```

├── Button/
│   ├── Button.vue              # 主组件文件
│   ├── button.types.ts         # 类型定义
│   ├── button.styles.css       # 样式文件
│   └── __tests__/              # 测试文件

│   ├── Table.vue
│   ├── TableColumn.vue         # 子组件
│   ├── table.types.ts
│   └── __tests__/
│       └── Table.test.ts
```

## 自动导入机制

### 如何工作？

通过`unplugin-vue-components`和自定义`packagesResolver`实现：

1. **自动扫描**：启动时扫描所有组件目录
2. **生成类型**：自动生成`components.d.ts`
3. **零导入使用**：直接在template中使用组件

### 使用示例

**无需手动导入**:
```vue
<script setup lang="ts">
// ❌ 不需要：import { LsButton } from '@smartabp/lowcode-shared'
// ✅ 直接使用即可
</script>

<template>
  <div>
    <!-- packages组件 -->
    <LsButton>共享按钮</LsButton>
    <LcCanvas />
    <LdToolbar />
    
    <!-- 主应用组件 -->
    <UserCard />
    <DataTable />
  </div>
</template>
```

### TypeScript类型提示

自动生成的`components.d.ts`提供完整的类型提示：

```typescript
// components.d.ts (自动生成，无需手动编辑)
declare module 'vue' {
  export interface GlobalComponents {
    // packages组件
    LsButton: typeof import('@smartabp/lowcode-shared/components/Button')['default']
    LcCanvas: typeof import('@smartabp/lowcode-core/components/Canvas')['default']
    
    // 主应用组件
    UserCard: typeof import('./src/components/UserCard.vue')['default']
    DataTable: typeof import('./src/components/DataTable.vue')['default']
  }
}
```

## 最佳实践

### ✅ DO（推荐做法）

1. **使用语义化前缀**
   ```vue
   ✅ <LsButton type="primary">确定</LsButton>
   ✅ <LcCanvasToolbar />
   ```

2. **保持组件单一职责**
   ```vue
   ✅ <LsUserAvatar :user="user" />
   ✅ <LsUserBadge :count="count" />
   ```

3. **组件Props使用TypeScript**
   ```vue
   <script setup lang="ts">
   interface Props {
     type?: 'primary' | 'success' | 'warning' | 'danger'
     size?: 'small' | 'medium' | 'large'
   }
   
   defineProps<Props>()
   </script>
   ```

4. **组件Events使用defineEmits**
   ```vue
   <script setup lang="ts">
   const emit = defineEmits<{
     click: [event: MouseEvent]
     change: [value: string]
   }>()
   </script>
   ```

### ❌ DON'T（避免做法）

1. **不要使用缩写前缀**
   ```vue
   ❌ <LButton>  (不清晰)
   ✅ <LsButton> (明确来自lowcode-shared)
   ```

2. **不要跨package直接引用**
   ```typescript
   ❌ import Button from '../../lowcode-shared/src/components/Button.vue'
   ✅ // 使用零导入，直接在template使用 <LsButton>
   ```

3. **不要在主应用组件使用前缀**
   ```vue
   ❌ src/components/AppButton.vue
   ✅ src/components/Button.vue
   ```

4. **不要使用any类型**
   ```typescript
   ❌ const props = defineProps<{ data: any }>()
   ✅ const props = defineProps<{ data: UserData }>()
   ```

## 常见问题

### Q1: 组件名冲突怎么办？

**答**: 使用前缀区分不同package的组件。

```vue
<!-- 场景：主应用和lowcode-shared都有Button组件 -->

<!-- 主应用Button -->
<Button>主应用按钮</Button>

<!-- lowcode-shared Button -->
<LsButton>共享按钮</LsButton>
```

### Q2: 如何知道组件来自哪个package？

**答**: 通过前缀立即识别。

| 前缀 | 来源 |
|------|------|
| `Ls` | lowcode-shared |
| `Lc` | lowcode-core |
| `Ld` | lowcode-designer |
| `La` | lowcode-api |
| `Lt` | lowcode-tools |
| `Mc` | metadata-core |
| 无前缀 | 主应用 |

### Q3: 自动导入不生效怎么办？

**排查步骤**:

1. **检查组件文件名**：必须是PascalCase
2. **检查目录配置**：确认在`vite.config.ts`的`dirs`中
3. **重新生成类型**：运行`npm run build:packages:types`
4. **重启开发服务器**：`npm run dev`

### Q4: 如何手动重新生成components.d.ts？

```bash
# 方法1: 重新构建packages类型
npm run build:packages:types

# 方法2: 重启开发服务器（自动生成）
npm run dev
```

### Q5: 可以不使用前缀吗？

**不推荐**。前缀的好处：

- ✅ 避免组件名冲突
- ✅ 快速识别组件来源
- ✅ 符合业界规范（Element Plus、Ant Design等）
- ✅ 更好的代码可维护性
